# 3 项目二：酷瓜云课堂

## 3.1 项目概览

| 项目 | 内容 |
|---|---|
| 项目名称 | 酷瓜云课堂（网校开源版，course-tencent-cloud） |
| 代码仓库 | https://gitee.com/koogua/course-tencent-cloud |
| 开源许可 | GPL-2.0 |
| 技术栈 | PHP + Phalcon（C 扩展框架），模板渲染；依托腾讯云基础服务（对象存储、点播、CDN） |
| 终端形态 | PC、H5、微信公众号、微信小程序 |
| 演示环境 | 前台 ctc.koogua.com；后台 ctc.koogua.com/admin（前后台通用演示账号，后台已禁用数据提交） |
| 定位 | 面向教育机构与知识付费的网校系统，支持点播、直播、专栏、问答、会员、积分 |

## 3.2 选择依据

1. **形态最贴近本平台的终端前提**。本平台处在微信生态内，学生大量通过公众号与 H5 进入。酷瓜是三个项目中唯一把“PC + H5 + 公众号 + 小程序”作为一等公民设计的，其页面在微信内置浏览器中的适配方式、登录后的会话维持方式，可直接观察。
2. **同时具备点播与图文两类课时**。本平台的核心内容形态正是“图文教程 + 视频教程”，酷瓜在课程类型上明确区分点播与图文，是三者中唯一在界面上把两类课时并列呈现的。
3. **进度表达接近“完成度”语义**。个人中心以“已学习时长 + 已完成百分比”呈现，与本平台 learning_progress 的两个关键字段（accumulatedSec、progressPercent）一一对应。
4. GPL-2.0 许可对私有化内部使用没有障碍，但若未来需要对外分发衍生代码，需评估开源义务——这一点与 PlayEdu 的 Apache-2.0 有实质差别。

## 3.3 与需求文档的对应关系

| 需求编号 | 需求名称 | 酷瓜对应能力 | 界面证据 | 覆盖判断 |

| FR-STU-03 | 课程分类浏览 | 方向（前端/后端/移动/数据库/计算机基础）页签与筛选 | 图 3-1、3-2 | 直接对应 |

[IMG:fig3_1.png] 图 3-1 前台首页：分类页签与课程推荐

首页采用“大图轮播 + 推荐课程 + 新上课程”的电商式结构，两段课程区都带分类页签（前端开发/后端开发/移动开发/数据库/计算机基础），点击页签在原位切换，不跳页。这个细节值得借鉴：本平台 FR-STU-03 要求“分类入口固定展示七个分类”，若每次点击都整页刷新，学生在七类之间比较课程的成本会很高；采用页签原位切换 + 路由参数同步（保证可分享、可回退）是更合适的做法。

[IMG:fig3_2.png] 图 3-2 课程列表：方向、类型、难度三重筛选

这是三个项目中筛选维度最完整的一屏。三行筛选分别是：方向（学科分类）、类型（点播/图文）、难度（入门/初级/中级/高级），与排序（综合/好评/最新/最热/推荐/免费）分离。本平台第 6 章为课程定义了 difficulty 字段，但 FR-STU-04 只要求“按分类、难度、完成状态筛选”，未把“内容类型”作为筛选条件——从这一屏可以看出，**当同一分类下既有视频课又有图文课时，类型筛选是必要而非可选的**，建议在 FR-STU-04 中补充。

[IMG:fig3_3.png] 图 3-3 课程详情：目录、课时时长与课程元信息

详情页右侧集中展示课程元信息（课程时长、学习期限、退款期限、价格、难度、学习人次、评分），左侧为目录。与本平台的差异在于：它把“学习期限 6 个月”作为课程属性——这对警务培训有现实约束（例如新警入职培训要求在 3 个月内完成），本平台当前未设计学习期限，属于需要评估的缺口。

课时行末展示每节时长（01分钟01秒），并要求登录后才能进入学习（行首锁图标）。本平台 FR-STU-05 规定未开始学习时按钮为“开始学习”，语义一致；但“锁定”与“未开始”在视觉上必须区分清楚，否则学生会误以为需要付费。

[IMG:fig3_4.png] 图 3-4 课时播放：播放器控制与课程目录侧栏

播放器提供清晰度切换、倍速、洗脑循环（连播）三项控制，右侧课程目录按章节分组、以数字序号排列课时，当前课时高亮。这一“播放器 + 目录常驻”的双栏布局，正是本平台 FR-STU-06/07 要求的“章节内连续切换”的合理形态，比 PlayEdu 的单页播放器更适合连续学习场景。

需要注意：目录侧栏的课时以序号（1、2、3…）呈现，没有课时标题，当一章内课时较多时难以定位。本平台应保留标题并辅以序号。

[IMG:fig3_5.png] 图 3-5 个人中心：在学课程与完成百分比

“在学课程”以卡片网格呈现，每张卡片下方两行数据：“已学习 05分钟30秒 / 已完成 2%”。这与本平台 FR-STU-08 要求的字段（进度百分比、最近学习时间）几乎一致，差异是它以“学习时长”替代了“最近学习时间”。

一个可借鉴的判断：它把“已完成 0%”的课程也保留在列表中（而非归入“未开始”），因为学生点进去过就算在学。本平台 3.4.5 规定“仅访问详情页未开始学习”不创建进度记录，两者口径不同——前者按“访问”计，后者按“实际学习”计。建议维持本平台的严格口径，但在界面上用“未开始”标签区分，避免学生困惑。

## 3.4 主要特点

| 特点 | 说明 | 对本平台的价值 |
|---|---|---|
| 多端覆盖 | PC/H5/公众号/小程序四端，同一套业务 | 微信生态内的落地形态参考 |
| 双课时类型 | 点播与图文并列，列表可筛选 | 直接印证本平台“图文 + 视频”双形态的必要性 |
| 三重筛选 + 排序 | 分类、类型、难度、排序相互独立 | 可细化 FR-STU-04 的筛选维度 |
| 播放页双栏 | 播放器与目录常驻，支持连续学习 | 对应 FR-STU-06/07 的交互形态 |
| 课程属性完整 | 时长、学习期限、难度、人次、评分 | 提示本平台缺少“学习期限”设计 |
| 会员与支付 | 会员、积分、订单体系 | 超出本平台边界，需整体剥离 |

## 3.5 局限与二次开发点

| 缺口 | 影响 | 建议 |
|---|---|---|
| 技术栈为 PHP 模板渲染 | 前端无法复用，仅能借鉴交互与信息结构 | 前端按 React + Ant Design 重写，不复用代码 |
| 问答、会员、积分、直播 | 与本平台边界冲突（社区属论坛，支付不在范围内） | 整体不引入；若参考其问答结构，须先确认归属平台 |
| 无审核状态机 | 不满足 3.3 节流程 | 自研 |
| 无开放接口 | 无法支撑跨平台取数 | 自研 |
| 本地账号体系 | 与“不自建账号”冲突 | 替换为论坛 OIDC |
| GPL-2.0 | 衍生分发有传染性 | 仅作设计参考，不复制代码 |
