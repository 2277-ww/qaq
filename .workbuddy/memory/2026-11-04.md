## Vercel 容器化全量方案（方案文档 + 脚手架）
- 关键发现：Vercel 2026 已有官方 **Container Runtime**（Beta，全套餐），根目录 `Dockerfile` 即可，镜像推到 VCR，默认监听 80/$PORT；另有 **Daemons**（仅 production、无 autoscaling、无公网 ingress，只能跑队列类进程，不能当 WS 入口）
- 硬限制（官方文档核对）：根只读 + `/tmp` 500MB；请求体 4.5MB；Hobby 2GB/1vCPU、300s；缩容 5 分钟；单区域；不支持 Secure Compute/静态 IP
- 因此全量路线 = 镜像内 PHP7.3+Phalcon3.4+nginx+fpm+vendor，MySQL/Redis/COS 外接，scheduler 改 `/cron/tick` + CRON_SECRET，WebSocket 必须外置或砍掉
- 脚手架 `deploy/vercel-container/`：Dockerfile（buster 切 archive 源、编译 phalcon 3.4.5、pecl igbinary/redis、双阶段复用扩展、构建期把 storage/{cache,log} 软链到 /tmp、opcache 关 stat）、nginx.conf（`_url` 伪静态 + 日志走 stdout）、entrypoint.sh（建 /tmp 目录、校验三扩展、fpm 后台 + nginx 前台、SIGTERM 转发）、vercel.json（hkg1 + crons）、.dockerignore（排除 1.3G 视频/_removed_*）
- 文档 `docs/Vercel容器化运行环境部署方案.md`：三种承载形态对照、架构图、依赖矩阵、6 处必改代码点、限制与替代方案（VPS/Render/Fly）、四层验证（镜像层/功能层/可观测/冒烟脚本）
- 未验证项：本机无 Docker（`docker` 未安装），Dockerfile 与镜像构建未实测；Docker Hub 与 hub.docker.com API 在本机被墙，无法确认 `php:7.3-fpm-buster` tag 仍可拉取 → 文档已给三条降级路径
