## 8.2 附录 B 业务事件说明

### B.1 course.completed 事件契约

**语义**：某用户首次完成某门课程。事件只表达“完成”这一事实，不表达“合格”“通过考核”“具备准入资格”等任何评价性含义。消费方不得将其直接等同于能力认证。

事件信封字段：

| 字段 | 类型 | 必填 | 示例 | 说明 |
|---|---|---|---|---|
| eventId | string | 是 | 01JCV9K2Q7X8M3N5P1R4T6W8YZ | ULID，消费方幂等键 |
| eventType | string | 是 | course.completed | 固定值 |
| eventVersion | string | 是 | 1.0 | 契约版本 |
| occurredAt | string | 是 | 2026-11-03T11:52:16+08:00 | 完成判定时间 |
| sourcePlatform | string | 是 | selfstudy | 平台编码 |
| producer | string | 是 | selfstudy-progress-service | 生产服务 |
| userId | string | 是 | u_8f3a1c... | 全局用户标识 |
| traceId | string | 是 | 7f2c9a1e4b6d | 链路追踪标识 |
| data | object | 是 | 见下表 | 事件载荷 |

载荷 data 字段：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| courseId | string | 是 | 课程标识 |
| courseTitle | string | 是 | 课程标题（便于消费方直接展示） |
| categoryCode | string | 是 | 分类编码，供档案方分类统计 |
| difficulty | string | 是 | 难度编码 |
| courseVersion | number | 是 | 完成时的课程版本 |
| completedAt | string | 是 | 完成时间，ISO8601 带时区 |
| totalLessons | number | 是 | 完成时的课时总数 |
| totalLearningSeconds | number | 是 | 该课程累计有效学习秒数 |

**不包含**的字段（明确排除，避免越界）：笔记内容、课时级明细、教师信息、项目或考试相关信息、任何评价性结论。

### B.2 触发与幂等规则

| 规则项 | 规定 |
|---|---|
| 触发点 | 课程进度由 IN_PROGRESS 变为 COMPLETED 的同一数据库事务内写入发件箱 |
| 唯一次数 | 同一 userId + courseId + courseVersion 仅一条事件；重复完成、课程升版均不再触发 |
| 事务一致性 | 业务数据提交成功则事件必在发件箱；事务回滚则事件不生成 |
| 幂等键 | 消费方以 eventId 去重；本平台保证 eventId 全局唯一且重投时不变 |
| 顺序 | 不保证不同用户、不同课程之间的顺序；同一用户的事件建议消费方按 occurredAt 排序 |
| 载荷上限 | 单条不超过 16KB；超出时须裁剪可选字段而非截断字符串 |

### B.3 投递机制

| 参数 | 取值 | 说明 |
|---|---|---|
| 投递模式 | 至少一次（at-least-once） | 允许重复，不允许丢失 |
| 首次投递 | 入箱后 5 秒内 | 由投递任务扫描触发 |
| 重试序列 | 1s、2s、4s、8s、16s、32s、64s、128s | 最多 8 次 |
| 超时 | 单次 10 秒 | 超时视为失败 |
| 成功判定 | 订阅方返回 2xx | 其他状态码均视为失败 |
| 死信 | 超过 8 次进入 DEAD | 告警 + 管理员可重放 |
| 对账 | 每日 02:00 | 比对完成记录与成功投递记录，差异补发 |
| 暂停 | 订阅方连续 7 天全部失败 | 暂停投递并通知联系人 |

### B.4 典型场景走查

**场景一：正常完成**。学生在 11:50 观看最后一个视频课时，覆盖率达 96%，服务端判定课时完成，课程全部课时完成，进度状态置为 COMPLETED，写入 completion 记录与发件箱记录，接口在 200ms 内返回 isCourseCompleted 为 true。学生页面展示完成标识。工坊在 5 秒内收到事件，更新项目侧的前置条件状态。

**场景二：重复学习**。学生完成后再次进入同一课程复习，进度不上调（已为 100%），状态不变化，不产生新事件。工坊侧不会因此重复计数。

**场景三：课程升版**。课程新增两个课时并通过审核，已完成的用户保持 COMPLETED，其 completedCourseVersion 仍为旧版本；新加入的学生按新版本判定，需完成全部课时。

**场景四：事件投递失败**。工坊服务在维护窗口返回 503，本平台按退避重试，第 3 次成功。期间工坊若主动调用 OPEN-01，也能查到最新完成状态，形成双通道兜底。

**场景五：课程归档后查询**。课程被归档，工坊调用 OPEN-01 仍能查到已完成学生的 COMPLETED 状态，同时 courseStatus 返回 ARCHIVED，工坊据此决定是否提示教师更换课程，但不影响已完成学生的资格事实。

## 8.5 附录 E 待确认事项

| 编号 | 事项 | 影响范围 | 建议处理 |
|---|---|---|---|
| Q-01 | 本平台在统一事件中的 sourcePlatform 编码未在约束规范中明确 | 事件对接 | 暂定 selfstudy，提交统一架构登记后固化 |
| Q-02 | 全局个人成长档案的服务归属方与承载平台未明确 | OPEN-04 对接方式 | 由统一架构确认；若由论坛侧承载，按其接口约定调整 |
| Q-03 | 前置必修绑定关系是否需要在自学平台留痕 | 边界与数据模型 | 建议维持“绑定由工坊持有”，本平台不存 projectId，仅保留深链来源标识用于展示提示 |
| Q-04 | 视频转码与播放是否统一由文件服务提供 HLS | 播放体验与进度判定 | 需文件服务确认；若不支持 HLS，按 MP4 单码率实现，覆盖率算法不变 |
| Q-05 | 课程审核是否需要教研室与教务处两级审核 | 流程与状态机 | 若需要，须在 PENDING_REVIEW 与 PUBLISHED 之间增加复审状态，本文件需同步修订 |
| Q-06 | 学习时长是否纳入学分或评优计算 | 数据口径 | 本期仅统计不结算；口径由教务确认后另立规则，不在本平台实现换算 |
| Q-07 | 教师是否需要查看本课程学员名单 | 隐私与边界 | 建议不提供，仅提供聚合统计，避免与工坊成员管理职责重叠 |
| Q-08 | 课程封面与视频的存储配额及清理策略 | 成本与运维 | 由统一文件服务制定，本平台仅登记引用与状态 |
| Q-09 | 是否存在跨年级复用的课程（同一课程多年级共用） | 数据归属与统计 | 建议一门课程全年级共用，统计按用户维度自然区分，不做班级维度建模 |
| Q-10 | 归档课程的完成记录在成长档案中是否继续展示 | 归集口径 | 建议继续展示并标注课程已归档，由档案方决定呈现方式 |
