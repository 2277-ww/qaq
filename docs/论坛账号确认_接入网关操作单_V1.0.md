## 三、失败码对照

按文档第四章整理。**只有 40104 与用户输入有关，其余都是接入问题，不要提示用户「密码错误」。**

| 码 | 含义 | 排查方向 |
| --- | --- | --- |
| `40105` | 签名头缺 / 算法不符 / 签名不一致 | 对照 canonical 七段；确认 `X-Sign-Alg: HMAC-SHA256`；确认 body 未经二次编码 |
| `40106` | 时间戳超 ±300s | 服务器校时（`chronyc tracking`），偏移 >30s 即告警 |
| `40107` | nonce 重复 | 每次请求必须重新生成；Redis `SET NX EX 600` |
| `40108` | AppKey 未登记或停用 | 核对 `jy-learning-svc` 拼写与网关白名单 |
| `40001` | 参数非法 | `login` 1–100 字符、`pass` 8–32 字符、`login_type ∈ {auto,username,email}` |
| `41300` | 体积超 64 KB | 正常请求不会触发，出现即检查是否误传了附件 |
| `40300` | 未登记路由 | 网关 `routes.py` 缺 `account-verify`，找网关管理员 |
| `40303` | 绕过网关直连 / 内部签名伪造 | 检查是否误配成直连 9088 |
| `42901` | 限流 | 200 QPS/AppKey、60 QPS/IP；按 `Retry-After` 退避 |
| `40104` + `invalid_credentials` | **账号或密码错误** | 唯一该提示用户的失败 |
| `40104` + `account_unavailable` | 账号停用/删除 | 提示联系管理员 |
| `50200` / `50400` | 上游不可达 / 超时 | 网关到论坛 9088 这一跳；稍后重试 |
| `50000` | 论坛内部错误 / 配置缺失 | 带 `requestId` 反馈运维，查 `journalctl -u jingyuan-wechat \| grep account-verify` |

## 五、一处有意为之的偏差

文档标注接口超时为 **3s**（S 级）。本平台配的是 **5s**（`gateway.account_timeout`）。

原因：3s 是「网关 → 论坛」这一跳的预算，本平台到网关还有一跳。客户端超时若要等于服务端超时，会在网关尚未返回时先断开，把「对端慢」误报成「网关不可达」。5s = 3s 网关预算 + 余量，注释已写在配置里。
