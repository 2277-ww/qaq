## 五、OIDC 阻塞的实测证据

按文档附录 C 第 1 条执行：

```
GET http://8.138.246.181/.well-known/openid-configuration
→ 200，但响应体是 Apache APISIX 默认页 HTML，
  与 GET /this-path-must-not-exist-12345 的响应逐字相同
```

`/oauth/authorize` 同样如此。说明网关有 `/oauth/*` 转发路由，但**论坛侧未实现标准端点**——网关部署报告第 161 行亦自述「标准 OAuth 端点缺失，论坛目前只有 `/answer/api/v1/account/verify` 自省」。

另：`auth.jingyuan.edu.cn`、`learning.jingyuan.edu.cn`、`api.jingyuan.edu.cn` 三个域名均解析到 `192.168.5.1`（私网），未在公网生效。

结论：OIDC 路线的前置条件（域名、Discovery、authorize/token/jwks、客户端注册）**全部未就绪**，不属本平台可独立推进的范围。

## 六、建议推进顺序

| 序 | 动作 | 依赖 | 理由 |
| --- | --- | --- | --- |
| 1 | 账号确认链路注入 AppSecret 并跑通 | 服务器权限 | 当前唯一可用的身份接入方式，只差一个值 |
| 2 | 补 `/courses`、`/notes`、`/auth/userinfo` 等契约接口 | 无 | 其余平台联动的基础；与身份方案无关，可并行 |
| 3 | `@Permission` 权限点与四重校验 | 依赖 2 | 有接口才谈得上权限点 |
| 4 | 幂等键落到 Redis | 依赖 2 | 只对写接口有意义 |
| 5 | OpenAPI 交付 | 依赖 2、3 | 契约定稿的标志 |
| 6 | OIDC 客户端 | 论坛侧端点 + 域名 | 端点就绪前只能写骨架，无法联调 |

第 2–5 项合计约 20 人日，是**不受外部阻塞**的部分；第 6 项在阶段零完成前不应启动。
