# 登录功能实现说明 V1.0

日期：2026-11-06
范围：自学平台（8.138.34.151:/www/ctc）前台登录能力

## 1. 背景与目标

登录功能上线前，平台的「登录」实际不可用：

- `config` 中 `identity.enabled=true`，`Home::getAuthInfo()` 不读会话、恒返回内置账号
  10000（所有人共享同一身份，含 admin_role）；
- `/account/forum-login` 只做论坛凭据代验与建号，**从不写入会话**，登录与否效果相同；
- 页头无任何登录/退出入口，`/account/login`、`/account/register` 在功能裁剪时移除（404）。

目标（用户选定）：

| 决策项 | 结论 |
| --- | --- |
| 登录方案 | 论坛账号登录（符合生态规范 SSO-01：论坛唯一身份源，不自建账号体系） |
| 匿名范围 | 课程浏览、搜索等公开内容匿名可看；仅个人中心（/uc/*）需登录 |

## 2. 改动清单（4 个文件 + 1 处配置）

| 文件 | 改动 |
| --- | --- |
| `app/Http/Home/Controllers/ForumLoginController.php` | ① 登录成功后调用 `auth->saveAuthInfo($user)` 建立真实会话（写 session + 登记 kg_user_session，单点登录语义：踢掉该用户其他会话）；② 新增 `GET /account/logout`（`home.forum_login.logout`）：清会话后 302 首页；③ 回跳支持：`redirect` 参数经 `sanitizeRedirect()` 消毒后贯穿「登录页 → 提交失败重渲染 → 成功跳转」 |
| `app/Http/Home/Views/account/forum_login.volt` | 表单增加隐藏字段 `redirect`（控制器已消毒，视图不裸输出） |
| `app/Http/Home/Views/partials/header.volt` | 未登录：页头显示「登录」入口；已登录：用户下拉菜单增加「退出登录」 |
| `app/Http/Home/Controllers/UserConsoleController.php` | 新增 `beforeExecuteRoute`：先走基类（站点关闭/CSRF/Referer），再判 `getAuthInfo()`，未登录 302 到 `/account/forum-login?redirect=<当前地址>` |
| `config/config.php` | `identity.enabled` true → false（`patch_identity_off.py`：精确单行替换 + 备份 + php -l 校验失败自动回滚） |

关键设计点：

1. **判定用 `getAuthInfo()` 而非 `getAuthUser()`**——游客时后者返回 id=0 的内置模型而非
   null，判不出「未登录」。
2. **回跳消毒**：只接受单 `/` 开头、不含 `:` 与控制字符、≤512 字节的站内相对路径；
   拒绝 `//`（协议相对）、外站 URL。实测 `redirect=https://evil.com/x` 登录后落回首页。
3. **`identity.enabled` 是登录生效的硬前提**：不关闭它，任何会话写入都被绕过
   （getAuthInfo 恒返回内置账号）。此开关与「统一身份接入说明」里描述的
   `getIdentityUser()` 不存在问题无关——生产版本 Auth 服务确实实现了该分支。
4. 关闭身份模式后，匿名访问课程/章节页走 `auth_user.id == 0` 的既有分支，行为正常。

## 3. 部署与回滚

部署：`deploy/login-feature/deploy.sh`（php -l → 备份 → 覆盖 → 关身份模式 → 清缓存 → 首屏自检）。
缓存清理覆盖 volt 编译缓存 + redis db3 的 `_PHCR_ANNOTATION_*` / `_PHCR_METADATA_*`
（新增路由注解 `home.forum_login.logout`，不清注解缓存会 404）。

回滚：备份位于 `/root/backup/login-feature-<ts>/`（4 文件 + config.php），
config 另有 `config.php.bak.<ts>`；同名路径拷回 + 重跑缓存清理即可。

## 4. 验收结果（2026-11-06 生产实跑，21/21 ALL PASS）

| 场景 | 结果 |
| --- | --- |
| 匿名 `GET /uc/progress` | 302 → `/account/forum-login?redirect=%2Fuc%2Fprogress` |
| 登录页（带 redirect） | 200，csrf_token 与 redirect 隐藏字段齐备 |
| 正确凭据登录 | 302 → 回跳 `/uc/progress`；进度页 200 |
| 登录态页头 | 退出入口出现，匿名「登录」入口消失 |
| 外站回跳消毒 | `redirect=https://evil.com/x` → 302 首页 |
| 错误密码 | 表单重渲染 200 + 错误文案；不建立会话 |
| 退出登录 | 302 首页；之后 `/uc/progress` 重新 302 登录页 |
| 匿名回归 | `/`、`/course/list` 200；页头出现「登录」入口 |
| 公网（https://8.138.34.151） | home 200、/uc 302 带回跳、登录页 200 |
| 日志脱敏 | gateway 通道记录 Succeeded/Rejected（userId、错误键、IP），密码明文 0 命中 |
| 会话登记 | kg_user_session 为 userId=20001 建档，有效期 24h |

验收脚本：`deploy/login-feature/verify_login.sh`（用法与既有
`verify_forum_login_http.sh` 一致，默认使用接口文档公开示例凭据）。

## 5. 限制与已知事项

1. **限流继承**：登录仍按 IP 10 次/60s 限流（LoginThrottle），本轮未改。
2. **会话有效期** 24h（session.lifetime 默认），不提供「记住我」。
3. `saveAuthInfo` 每次登录插入一条 kg_user_session 记录（不删除旧行），过期行由
   expire_time 语义约束；如需整洁可后续加清理任务。
4. 既有开放问题不受影响：D1 联调账号（kg_account 20001）是否删除、网关侧
   G1–G6/I1–I8 待办见《接入网关_剩余问题与待补信息清单》。
5. repro/src 中 `UserConsoleController.php` 保持上游原版（与生产裁剪版差异大），
   本轮生产版改动只存于 `deploy/login-feature/`，以线上为准。
