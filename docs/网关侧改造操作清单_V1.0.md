> 日期：2026-11-06　执行方：**网关方**（本平台无网关机权限，Admin API 9180 公网不可达，仅网关机本机可用）
> 依据：本平台对网关 `http://8.138.246.181` 的全部公网实测（探针脚本可复跑）+ 网关方《部署报告》表 6/表 7 + 双方接口说明
> 目标：把剩余 5 项网关侧阻塞项一次改完。每项都给了「改动内容」与「验证方法」，改完即可由本平台复测闭环。

## 0. 网关现状（本平台实测基线）

架构：APISIX 3.13 + 自研插件 `jy-l2-sign`（L2 五头验签）/ `jy-identity`（剥离伪造身份头、注入七头 + X-Internal-Sign）/ `jy-gw-error`。路由按平台分组，internal 路由走 L2，上游为**网关机本机回环**（learning 8080 / exam 8090 / workshop 8000 / plaza 8081，公网全部不可达）。

**路由组白名单实测**（2026-11-06，用四个平台各自的 L2 AppSecret 对照实验）：

| 路由组 | 路径前缀 | 白名单（实测/表 6） | 本平台打它 |
| --- | --- | --- | --- |
| learning-internal | `/api/v1/learning/internal/*` | exam、workshop | 40108（不在白名单） |
| exam-internal | `/api/v1/exam/internal/*` | workshop、plaza | 40108 |
| workshop-internal | `/api/v1/workshop/internal/*` | plaza、exam | 40108 |
| plaza-internal | `/api/v1/plaza/internal/*` | workshop、**learning** | **200 sign_valid:true** |
| forum（事件） | `/api/v1/forum/*` | **路由未登记**（catch-all 默认页） | 无法投递 |

**网关 L2 错误码模型**（排障对照，改配置时可据此定位问题层级）：

| 现象 | 返回 |
| --- | --- |
| 签名头缺失/不全 | 40105「服务签名头不全」 |
| AppKey 不在路由组白名单 | 40108「AppKey 不存在或已停用」 |
| 白名单内 AppKey 但签名错 | 40105「服务签名校验失败」 |
| 重复 X-Timestamp 头 | 40106「时间戳格式非法」 |
| 时间戳超窗 ±300s | 40106 |
| 路由未登记 | 200 + APISIX 默认页 HTML（catch-all，**不是** 40300） |

## 1. 改动清单（按优先级）

### G1 ｜ 把 `jy-learning-svc` 加入 exam-internal、workshop-internal 白名单 【阻塞学习进度推送，最优先】

**现状**：本平台向 `POST /api/v1/exam/internal/learning/progress`、`/api/v1/workshop/internal/learning/progress` 推送结课事件，带有效 L2 签名，均被 **40108** 拒（AppKey 不在白名单）。

**改动**（routes.py 约 163–171 行 exam-internal、173–181 行 workshop-internal 的 `jy-l2-sign.app_keys`）：

```yaml
# exam-internal：app_keys 从 [jy-workshop-svc, jy-plaza-svc]
#               改为
- id: exam-internal
  uri: /api/v1/exam/internal/*
  plugins:
    jy-l2-sign:
      app_keys: [jy-workshop-svc, jy-plaza-svc, jy-learning-svc]   # ← 追加

# workshop-internal：同理追加
    jy-l2-sign:
      app_keys: [jy-plaza-svc, jy-exam-svc, jy-learning-svc]       # ← 追加
```

**验证**：改完后本平台复测投递探针（`probe_deliver.php`），预期 40108 → 2xx/业务响应（若仍 404「未定义的契约接口」见 G6）。

### G2 ｜ 把 `jy-learning-svc` 加入 learning-internal 白名单 【便于本平台自测，建议一并做】

**现状**：本平台无法用自己的 AppKey 自测入站链路（40108），入站联调只能靠 exam/workshop 代发。

**改动**（routes.py 约 153–161 行 learning-internal）：

```yaml
- id: learning-internal
  uri: /api/v1/learning/internal/*
  plugins:
    jy-l2-sign:
      app_keys: [jy-exam-svc, jy-workshop-svc, jy-learning-svc]    # ← 追加
```

**验证**：本平台用 jy-learning-svc 签名打 `/api/v1/learning/internal/peers/forum/handshake`，预期 40108 → 200。

### G3 ｜ learning 上游从回显桩切到本平台 【阻塞入站，必做】

**现状**：`127.0.0.1:8080` 后面是**回显桩**（`/api/v1/learning/auth/*` 返回 `{"platform":"learning","sign_valid":true,...}` 的桩响应），真实流量从未到达本平台 `8.138.34.151`。本平台只监听 443（Let's Encrypt IP 证书，公信链），80 属广场 Halo。

**改动**：把 8080 回环的反代目标指向 `https://8.138.34.151:443`（保留 nginx 前置或直接改 APISIX upstream 节点均可）：

```nginx
# 网关机 127.0.0.1:8080 的反代目标，替换现有桩
proxy_pass https://8.138.34.151:443;
proxy_ssl_server_name on;
# Let's Encrypt IP 证书，公信链，无需 proxy_ssl_verify off
proxy_read_timeout 10s;
```

或直接改 APISIX upstream（不经 8080 中转）：

```yaml
upstreams:
  - id: learning-api          # 学习平台各路由共用的 upstream_id
    type: roundrobin
    scheme: https
    nodes:
      "8.138.34.151:443": 1
    timeout: { connect: 2, send: 3, read: 5 }
```

> 超时 `read: 5` 与本平台 `gateway.timeout = 5` 对齐，避免网关先断开。

**路径不要重写**：本平台 nginx 已就绪两种形态——`/api/v1/learning/*`（真实路由）与 `location ^~ /api/v1/learning/internal/` rewrite 剥离兜底，网关转发时保留原路径即可。

**验证**：本平台复跑 `verify_inbound_sign.py`（8 组），并请网关方从 anonymous 桩路由 `/api/v1/learning/auth/*` 确认响应由本平台 404/JSON 变为回显桩消失；更直接的判据：`sign_valid` 字段不再出现在 auth 响应里（那是桩特有回显）。

### G4 ｜ 新建 forum 事件路由 【阻塞 forum 推送，必做】

**现状**：本平台向论坛推送 `course.completed` 的路径 `/api/v1/forum/internal/learning/progress` 落 catch-all，返回 APISIX 默认页 HTML——网关没有任何 `/api/v1/forum/*` 事件路由（论坛自身 API 挂在 `/answer/*` 下）。

**改动**（新增路由，插件配置**复制 forum-internal 现有条目**，勿手写——漏 `jy-l2-sign` 等于公网裸奔）：

```yaml
routes:
  - id: forum-learning-events
    uri: /api/v1/forum/internal/*
    methods: [GET, POST]
    upstream_id: <forum 现有 upstream_id>      # 论坛应用，网关方自知
    priority: 2600
    plugins:
      jy-l2-sign:
        app_keys: [jy-learning-svc]             # 至少放行本平台
      jy-identity:
        inject: [X-User-Id, X-User-Role, X-Client-Id, X-Token-Exp,
                  X-Request-Id, X-Auth-Mode, X-Timestamp]
        sign: X-Internal-Sign
      limit-count:
        count: 100
        time_window: 1
        key_type: var
        key: http_x_app_key
```

> 路径命名请网关方定夺（`/api/v1/forum/internal/*` 或其它）；**定稿后告知本平台**，我方同步 `peers.forum.push_path`。

**验证**：无签名打该路径应 40105（路由已生效、L2 档）；带 jy-learning-svc 有效签名应过验签（404/业务响应均说明已到论坛上游）。

### G5 ｜ 提供 `X-Internal-Sign` 的拼接规范 【阻塞入站终验，需书面确认】

**现状**：本平台 `TrustedHeader` 按七头顺序 `X-User-Id / X-User-Role / X-Client-Id / X-Token-Exp / X-Request-Id / X-Auth-Mode / X-Timestamp`、`\n` 拼接、HMAC-SHA256（密钥 `internal.learning.secret`）校验。桩回显证明网关注入的七字段名与顺序与之**一一对应**，但 canonical 的分隔符、空值处理、大小写规则未书面给出。

**需要**（任一即可）：
- jy-identity.lua 的 canonical 拼接片段（几行即可）；或
- 一次真实转发到上游的完整请求头样本（签名值可脱敏）。

**验证**：G3+G5 完成后，本平台从「自签自验」升级为「网关注入头实收实验签」，入站闭环。

### G6 ｜ （随附，非网关项）exam/workshop 侧接收端点

- **exam 上游未实现**：用白名单内键（jy-workshop-svc）实测打到 exam，返回 404 `未定义的契约接口：POST /api/v1/exam/internal/learning/progress` —— exam 有契约注册框架但未定义此接口。需 exam 团队实现接收端点（或告知真实契约路径，本平台对齐 `push_path`）。
- **workshop 上游是回显桩**（200 sign_valid），同样未实现。

## 2. 执行方式提示（网关机本机）

Admin API 仅网关机本机可达（公网 9180 超时）。在网关机上：

```bash
# 查看当前路由（确认字段名与本清单一致）
curl -s http://127.0.0.1:9180/apisix/admin/routes/exam-internal \
     -H 'X-API-KEY: <admin_key>' | python3 -m json.tool

# 改白名单：PUT 整个 route 对象（先 GET 取全量、改 app_keys 后 PUT 回写）
```

若网关方按 `routes.py` 部署，则直接改 routes.py 对应行后重跑部署脚本并 reload APISIX，效果相同。

**改完任一项后**：告知本平台，我方用现成探针复测（投递探针 / 入站验签 8 组 / plaza 对照组），当场出结论。

## 3. 优先级与依赖关系

```
G1（exam/workshop 白名单）──┐
G4（forum 路由）            ├─ 出站推送三链路放行（配合 G6 对端实现才能端到端成功）
G2（learning 白名单）       ├─ 入站自测能力
G3（upstream 切真）         ├─ 入站真实流量（前置：本平台 443 已就绪，随时可接）
G5（签名规范）              ┘ 入站终验
```

- G1/G2/G4 是纯白名单与路由新增，**不触碰既有 exam/workshop/plaza 流量**；
- G3 只影响 learning 路由组，exam/workshop/plaza 的回环不受影响；
- 全部改动均可通过 Admin API 单条回滚。
