# 学生学习进度窗口与考试平台对接说明 V1.0

> 平台：自学平台（learning）｜文档日期：2026-11-05｜状态：已上线并实测通过

## 1　这次加了什么

在用户中心新增一个**「学习进度」窗口**，把学生的课程学习进度汇总展示出来，并支持**一键/单课程推送到考试平台**。推送不是页面直接调考试平台，而是走「本地事实 → 发件箱 → 统一网关 → 考试平台」这条链路，失败可退避重试、可重放，页面能看见每条事件的状态。

同时预留了 5 个对外接口，供考试平台或成长档案回源取数。

```
学生/教师浏览器 ──► /uc/progress（窗口）
                       │ 点「同步到考试平台」
                       ▼
              kg_exam_outbox（发件箱，事务外异步投递）
                       │ exam_sync 定时器 / 即时投递
                       ▼
              统一网关（X-Internal-Sign 签名）
                       │
                       ▼
              考试平台 /api/v1/exam/learning/progress
```

反方向（考试平台取数）：

```
考试平台 ──► 网关 ──► GET /api/v1/learning/completion/{userId}/{courseId}
```

## 2　窗口

- 入口：用户中心 → 学习中心 → **学习进度**，路径 `/uc/progress`
- 截图：`docs/theme-shots/progress_1440.png`（首屏）、`docs/theme-shots/progress_full.png`（整页）

页面分区：

| 区域 | 内容 |
| --- | --- |
| 统计卡 | 学习课程数、已完成课程、完成课时（x/y）、累计学习时长 |
| 通道条 | 当前投递模式（经统一网关 / 本地直连）、网关地址、待推送/已推送/待重试/失败计数、最近推送时间 |
| 各课程进度 | 课程、进度条与百分比、课时/时长、最近学习、考试平台推送状态、单条「推送」按钮 |
| 同步记录 | 最近 15 条事件的类型、课程、进度、状态、发生时间、事件编号、重试次数 |
| 说明 | 上报口径、传输方式、考试平台回源接口 |

交互约定：

- 右上角「同步到考试平台」= 把当前所有课程的最新进度补入发件箱并投递；
- 行内「推送」= 只推该课程；
- 未开始（进度 0）的课程按钮置灰，不会产生空事件；
- 推送结果为 0 条时提示「当前进度已是最新，无需重复推送」，不会报错。

### 进度口径

- 课程进度 = 已完成课时数 / 课程总课时数（沿用平台原有 `kg_course_user.progress`，不另算一套）；
- 课时完成判定沿用 `SyncLearningTask`：点播观看超过时长 30%、直播超过 10 分钟、图文浏览即完成；
- 课程完成 = `kg_course_user.status = 2`，完成时间取 `complete_time`，只写一次。

## 3　推送事件

### 3.1 事件类型

| eventType | 触发 | 考试平台用途 |
| --- | --- | --- |
| `learning.progress.updated` | 进度增量（默认每 ≥5 个百分点入箱一条） | 更新学情、开放阶段性练习 |
| `course.completed` | 课程首次完成（去重，只入箱一次） | 开放随堂测试 / 结业判定 |

节流与去重规则（`App\Services\Learning\Collect`）：

1. 进度必须单调不减，回退的上报直接丢弃；
2. 距上次入箱不足 `exam.min_progress_delta`（默认 5）个百分点时合并，等下一条；
3. 完成事实按 (eventType, userId, courseId, eventVersion) 去重，重放不会重复入箱。

### 3.2 事件封套

```json
{
  "eventId": "evt_22878D8040895A3C4D9D",
  "eventType": "course.completed",
  "eventVersion": "1.0",
  "occurredAt": "2026-11-05T10:22:50Z",
  "sourcePlatform": "learning",
  "sourceEntityId": "course_2",
  "actorId": "usr_10000",
  "correlationId": "flow_9A1C3F2D7B45",
  "requestId": "0e16e6ae-4792-4d7f-b44b-8874db99fd57",
  "data": {
    "userId": "usr_10000",
    "courseId": "course_2",
    "courseTitle": "Python 算法入门",
    "progress": 100,
    "completedChapters": 4,
    "totalChapters": 4,
    "durationSec": 1800,
    "completed": true,
    "completedAt": "2026-11-03T10:28:30Z",
    "status": "completed",
    "ruleVersion": "v1"
  }
}
```

字段口径按《自学平台统一身份与网关接入说明》8.2：`sourcePlatform` 固定 `learning`（不再是 `selfstudy`），`occurredAt` 统一 UTC（Z），ID 全部为字符串。

### 3.3 网关请求头

| 头 | 值 |
| --- | --- |
| `Content-Type` | `application/json` |
| `X-App-Code` | `learning`（配置 `gateway.app_code`） |
| `X-Request-Id` | 入箱时生成的请求 ID，全链路沿用 |
| `Idempotency-Key` | 事件 `eventId`，重放保持不变 |
| `X-Auth-Mode` | `service` |
| `X-User-Id` | 事件所属学生对外主键 |
| `X-Timestamp` | 当前秒级时间戳 |
| `X-Internal-Sign` | 见下 |

签名串固定 7 段、`\n` 分隔、顺序不可调：

```
X-User-Id \n X-User-Role \n X-Client-Id \n X-Token-Exp \n X-Request-Id \n X-Auth-Mode \n X-Timestamp
X-Internal-Sign = hex(HMAC-SHA256(gateway.internal_sign_secret, canonical))
```

### 3.4 投递与失败处置

| 情况 | 处置 |
| --- | --- |
| 2xx | `status=1` 已发送，记录 `sent_at`、响应码 |
| 5xx / 网络失败 / 超时 | `status=2` 待重试，`retry_count+1`，按 1s→5s→30s→2min→10min→1h 退避 |
| 4xx | 属契约错误，**不重试**，直接 `status=3` 死信并告警（`retry_count=1` 记录现场） |
| 第 6 次仍失败 | 转死信，写 `dead_at` |

死信重放（保留原 `event_id`，下游按 eventId 幂等）：

```bash
cd /www/ctc
php console.php exam_sync replay evt_XXXXXXXXXXXX
```

### 3.5 发件箱表 `kg_exam_outbox`

与成长档案通道 `kg_growth_outbox` 分表：两条链路的退避、死信、重放互不影响。

| 字段 | 说明 |
| --- | --- |
| `event_id` | 唯一键，`evt_` + 20 位十六进制 |
| `event_type` / `event_version` | 事件类型与版本 |
| `user_id` / `course_id` | 内部主键，用于查询与节流 |
| `user_key` / `course_key` | 对外主键（`usr_x` / `course_x`） |
| `progress` | 入箱时进度，节流比较用 |
| `payload` | 完整事件封套 |
| `status` | 0 待发 / 1 已发 / 2 待重试 / 3 死信 |
| `retry_count` / `next_retry_at` / `last_error` | 重试控制与排障 |
| `response_code` | 网关返回码，0 表示网络层失败 |

DDL：`deploy/learning-progress/exam_outbox.sql`，Phinx 迁移：`db/migrations/20261105180000.php`。

## 4　预留接口（考试平台 → 网关 → 本平台）

前缀 `/api/v1/learning`，控制器 `App\Http\Api\Controllers\LearningController`。

| # | 方法 | 路径 | 说明 |
| --- | --- | --- | --- |
| 1 | GET | `/progress/{userId}` | 全量进度快照（概览 + 每门课进度 + 推送状态） |
| 2 | GET | `/progress/{userId}/{courseId}` | 单课程进度明细 |
| 3 | GET | `/completion/{userId}/{courseId}` | 课程完成状态，**考试准入的权威回源点** |
| 4 | POST | `/progress/push` | 服务态触发推送（body: `userId`、可选 `courseId`），必带 `Idempotency-Key` |
| 5 | GET | `/sync/{eventId}` | 单条事件投递状态 |

统一响应体：

```json
{"code":"OK","message":"success","data":{...},"requestId":"8c20d1e4-..."}
```

错误码：`OK` / `VALIDATION_ERROR`(400) / `AUTH_REQUIRED`(401) / `FORBIDDEN`(403) / `NOT_FOUND`(404)。

完成状态示例：

```json
{"code":"OK","message":"success","data":{
  "userId":"usr_10000","courseId":"course_1","completed":true,"progress":100,
  "completedChapters":4,"totalChapters":4,"completedAt":"2026-11-03T10:28:30Z",
  "recordId":"rec_2","ruleVersion":"v1"
}}
```

入站安全：

- 只信任网关注入的 `X-User-Id` / `X-User-Role` / `X-Auth-Mode` 等头；
- `gateway.verify_sign=true` 时校验时间戳偏移（默认 300s）与 `X-Internal-Sign`，不通过返回 401；
- 用户态只能读自己（`X-User-Id` 与路径 `userId` 一致），服务态（`X-Auth-Mode: service`）可读任意用户；
- 响应头回传同一个 `X-Request-Id`，便于全链路追踪。

## 5　配置项

写入 `config/config.php`（模板：`config/config.default.php`）：

```php
$config['gateway']['base_uri'] = '';                       // 网关入口，如 https://api.jingyuan.edu.cn
$config['gateway']['app_code'] = 'learning';
$config['gateway']['internal_sign_secret'] = '';           // 与网关约定，生产必填，禁止入库
$config['gateway']['verify_sign'] = false;                 // 生产置 true
$config['gateway']['timestamp_skew'] = 300;
$config['gateway']['timeout'] = 5;

$config['exam']['enabled'] = true;                         // 总开关
$config['exam']['push_path'] = '/api/v1/exam/learning/progress';
$config['exam']['user_prefix'] = 'usr_';                   // 未接 OIDC 前的对外主键前缀
$config['exam']['min_progress_delta'] = 5;
$config['exam']['retry_max'] = 6;
```

`base_uri` 留空 = **本地直连模式**：事件照常入箱，投递直接标记成功，页面明确标注「本地直连（未配置网关地址）」，用于演示与联调。填入网关地址后无需改代码，自动改走网关。

## 6　上线步骤（已执行）

```bash
# 1. 建表
mysql -uctc -p*** ctc < deploy/learning-progress/exam_outbox.sql

# 2. 上传新增/修改文件（备份：/root/ctc_learning_progress_backup_<时间戳>）

# 3. 清注解缓存（新控制器要重新注册路由）
redis-cli -n 3 eval "local ks=redis.call('keys',ARGV[1]); for i=1,#ks do redis.call('del',ks[i]) end; return #ks" 0 '_PHCR_ANNOTATION_*'

# 4. 清模板缓存并重载
rm -f storage/cache/volt/_www_ctc_app_http_home_views_user_console_progress.volt.php
systemctl reload php-fpm

# 5. 定时器（scheduler.php 已加）
#    exam_sync main  每分钟第 3 秒
```

> 坑：注解缓存键前缀是 `_PHCR_ANNOTATION_`（不是 `_METADATA_`），用 `xargs` 批量删会被键名里的反斜杠转义搞失效，用 `eval` 循环删。
> 坑：`chown -R` 目标必须是 `apache`（php-fpm 实际用户），写成 `nginx` 会全站 500。

## 7　验收记录（2026-11-05 实测）

| 项 | 结果 |
| --- | --- |
| `/uc/progress` 首屏 | 200，9 门课渲染正常，无 JS 错误、无横向溢出 |
| 一键同步 | `{"sent":4,"queued":4,"mode":"local"}`，发件箱 4 条 → 2 条完成 + 2 条进度 |
| 重复同步 | `{"sent":0,"queued":0}`，提示「已是最新」，验证幂等 |
| 单课程推送 | 正常，仅该课程入箱 |
| `GET /completion` | 200，返回 `completed=true, progress=100, ruleVersion=v1` |
| 不存在课程 / 用户 | 404 `{"code":"NOT_FOUND"}`，不是站点 404 页 |
| 网关不可达（`127.0.0.1:9`） | `status=2`、`retry_count=1`、`next_retry_at=+1s`，错误为连接失败 |
| 网关返回 404 | `status=3` 死信、`response_code=404`，不再重试 |
| `exam_sync replay <eventId>` | 重放成功，`status` 回到 1 |
| 开启 `verify_sign` 无签名 | 401 `AUTH_REQUIRED` |
| 开启 `verify_sign` 正确签名 | 200，`requestId` 与请求头一致 |

## 8　预留与待办

1. **真实网关地址与密钥**：填 `gateway.base_uri` 与 `internal_sign_secret`，并把 `verify_sign` 打开；上线前需与网关方核对签名串顺序与时间戳窗口。
2. **考试平台推送路径**：`exam.push_path` 目前按 `/api/v1/exam/learning/progress` 占位，需考试平台给出正式路径与字段确认（尤其 `courseId` 是否为 `course_x` 形态）。
3. **身份主键**：当前对外主键为 `usr_<kg_user.id>`；接入 OIDC 后，只要 `kg_identity_binding` 有数据，`IdentityKey` 自动改用 `sub`，业务代码无需改动。接口本身接受任意 `usr_*` 形态，联调期可直接用。
4. **权限点**：`progress:read` / `progress:write` 的权限点校验依赖网关下发的 `X-User-Role`；当前仅在服务态放开，角色到权限点的映射待统一架构确认后接入。
5. **限流**：`PUT /progress/{userId}/chapters/{chapterId}` 这类高频上报（如需要）应按接入说明 5.4 做 5s 节流，本期未开放该接口。
6. **消费侧**：若后续引入「考试通过 → 结业状态」，需新增 `kg_inbox_event` 做 eventId 幂等消费（接入说明 8.5），本期未做。
