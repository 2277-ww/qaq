# 论坛账号登录 · 对接说明 V1.0

> 依据：《警院WeChat五平台_论坛账号确认接口说明》v2.2.0
> 目标接口：`POST http://8.138.246.181/answer/api/v1/account/verify`
> 实现提交：本地 main，改动待提交

---

## 一、定位与边界

这次接的不是推送，是**身份来源**：学生用警院论坛账号登录自学平台，密码由论坛校验，本平台只接受结论。

| 项 | 本平台做什么 | 本平台不做什么 |
| --- | --- | --- |
| 凭据校验 | 把账号密码经网关交给论坛确认 | 不校验论坛密码，不保存论坛密码 |
| 会话 | 确认通过后建立**自己的会话** | 不使用、不获取论坛 token |
| 账号数据 | 首次登录建本地账号并记录 `forum_uid` | 不修改论坛任何数据（接口本身也是只读） |
| 权限 | 映射讲师/学员 | 不把论坛 admin 映射为后台管理员 |

与学习进度推送的关系：两条完全独立的链路，共用同一套 L2 签名实现（`GatewaySign`），但**不共用网关地址配置**——推送侧 `gateway.base_uri` 为空表示「不外发」，账号确认必须真实走网关，借同一个值会让两种情况无法区分。

## 二、调用链

```
登录页（论坛账号 tab）
      │  POST /account/forum/login  {account, password}
      ▼
本平台 Account::loginByForum
      │  ① IP 限流（10 次/60s）
      │  ② AccountVerify::verify()
      ▼
网关 8.138.246.181  /answer/api/v1/account/verify
      │  L2 五头校验 → 剥离伪造头 → 注入七头 + X-Internal-Sign
      ▼
论坛 127.0.0.1:9088  只读查 user / registered_account / user_role_rel + bcrypt
      │  返回 confirmed + user_id / username / role / 掩码邮箱
      ▼
本平台 ForumLogin::handle
      │  ③ 按 forum_uid 找本地账号，找不到则建号
      │  ④ saveAuthInfo → 本平台会话
      ▼
登录成功，跳回 return_url
```

## 三、三个设计决定

### 3.1 首次登录自动建号

统一身份的意义是「一个论坛账号登录所有平台」。若要求用户先在本平台注册一次，等于把门槛原样加回来。因此 `confirmed=true` 且本地无对应账号时直接建号。

建号只插 `kg_account`，`kg_user` 与 `kg_user_balance` 由 `Account::afterCreate` 自动生成，不重复实现。

### 3.2 自动建的号没有可用密码

写入的是 `hash(bin2hex(random_bytes(32)), salt)`，**不是空串**。

原因：本平台密码校验是 `md5(md5(pwd) . md5(salt))`。若存空串，所有论坛账号的密码哈希只取决于 salt，一旦某个 salt 与哈希被拿到，就能反推出「密码为空」这条规律；更糟的是任何基于空值的特殊分支都可能被利用。存 32 字节随机数则任何输入都匹配不上，这些账号走本地密码登录恒为失败。

> 附带说明：本平台密码哈希是单轮 md5 组合，强度低于论坛的 bcrypt。这是既有实现，本次不改——改动会影响全部存量账号，属于独立议题。

### 3.3 论坛角色不映射到后台权限

- `student` → `edu_role=1`（学员）
- `teacher` → `edu_role=2`（讲师）
- `admin` → **按学员处理**，`admin_role` 保持 0

两个平台的「管理员」是两套独立概念。自动把论坛 admin 提成本平台后台管理员，等于让论坛的权限边界悄悄延伸到本平台后台，而论坛侧完全感知不到。讲师角色是安全的：`edu_role` 只影响教学内容展示，不涉及后台。

### 4.3 数据

```sql
ALTER TABLE kg_account
  ADD COLUMN forum_uid  INT UNSIGNED NULL DEFAULT NULL COMMENT '论坛用户主键，NULL 表示未绑定',
  ADD COLUMN forum_name VARCHAR(64) NOT NULL DEFAULT '' COMMENT '论坛用户名',
  ADD UNIQUE INDEX idx_forum_uid (forum_uid);
```

两点说明：

1. `forum_uid` 默认 NULL 而不是 0，因为唯一索引下所有存量账号的 0 会互相冲突；MySQL 允许多个 NULL，正好表达「未绑定」。
2. `email` / `phone` 保持空串。二者在 `kg_account` 上是普通索引（KEY）而非 UNIQUE，多个空串可以共存。**不能**拿掩码邮箱（`a***@jspi.edu.cn`）写进 email——用户之后绑定真实邮箱会撞「邮箱被占用」。

## 五、配置

| 键 | 值 | 说明 |
| --- | --- | --- |
| `gateway.account_base` | `http://8.138.246.181` | 留空则登录页不显示论坛入口 |
| `gateway.account_path` | `/answer/api/v1/account/verify` | 论坛侧改路径时只改这里 |
| `gateway.account_timeout` | `5` | 网关 S 级 3s，这里留一跳余量 |
| `gateway.account_login_limit` | `10` | 与网关 `/oauth/*` 口径一致 |
| `gateway.account_login_window` | `60` | 秒 |

`app_secret` 复用 `gateway.app_secret`（与推送同一把，来自 `secrets.json` 的 `app_keys.jy-learning-svc.secret`）。缺失时 `isEnabled()` 为 false，登录页直接不展示入口，不会出现必然失败的按钮。

## 六、上线与验证

### 6.1 顺序

```bash
# ① 迁移（必须先于代码：新代码会查 forum_uid）
php vendor/bin/phinx migrate

# ② 部署代码 + 清缓存
redis-cli -n 3 eval "local ks=redis.call('keys','_PHCR_ANNOTATION_:*'); for i,k in ipairs(ks) do redis-cli('del',k) end; return #ks" 0
rm -f storage/cache/volt/*.php
systemctl reload php-fpm

# ③ 注入密钥（与推送同一把，若已注入则跳过）
./apply_forum_peer.sh --config /www/ctc/config/config.php --secrets /etc/jingyuan-gateway/secrets.json

# ④ 验收
python3 verify_account_link.py --group gateway --secrets /etc/jingyuan-gateway/secrets.json \
        --login <真实账号> --password '<真实密码>'
python3 verify_account_link.py --group platform --base http://127.0.0.1
```

### 6.2 已完成验证

| 项 | 结果 |
| --- | --- |
| 公网路由存在性 | `/answer/api/v1/account/verify` 无签名返回 **40105**（非 40300），确认路由已登记 |
| 缺签名 / 篡改签名 | 40105 |
| 时间戳超窗 | 40106 |
| 未知 AppKey | 40108 |
| 与论坛 `account_verify_client.py` 签名对拍 | **5/5 一致**（ASCII、中文、`\u` 转义、含斜杠、空体） |
| 11 个 PHP 文件语法 | 全部通过 |

`verify_account_link.py` 在密钥错误时会在 A5 早停并明确提示「密钥被网关拒绝」，不会把后续用例的 40105 堆成一屏失败——那样最容易让人误判成签名算法写错。

### 6.3 尚未验证（需要真实账号）

以下用例需要一组真实的论坛账号密码，本地无法完成：

- 正确凭据 → `confirmed=true` 且返回 role/掩码邮箱
- 错误密码与不存在账号返回同一结论（防枚举）
- 首次登录建号 → `kg_account.forum_uid` 写入、`kg_user.name` 变为论坛昵称
- 二次登录复用同一账号（不重复建号）
- 论坛不可达时登录页提示可读文案而非 500

## 七、风险与遗留

| # | 项 | 说明 | 处置 |
| --- | --- | --- | --- |
| 1 | 密码代验 | 用户密码会经网关转发给论坛，论坛文档自己也把这条列为待演进项 | 正式对外建议改授权码 + PKCE（依赖域名与 HTTPS），平台不再接触密码 |
| 2 | 成为论坛接口的代理入口 | 本平台登录接口可被用来对论坛做密码尝试 | 已加 10 次/60s/IP 限流；论坛侧另有防枚举与 200 QPS |
| 3 | 论坛账号删除后的本地残留 | 论坛删号后本平台账号仍在，但无法再登录 | 需人工处理；后续可加「对账任务标记孤立账号」 |
| 4 | 限流按 IP 可被代理绕过 | 分布式尝试可分摊到多 IP | 与网关口径一致，属于可接受残余风险 |
| 5 | 论坛 `account_unavailable` 未实测 | 线上 5 个账号状态均为 normal | 代码已覆盖，需在测试环境置位验证 |
| 6 | 日志含 login 明文 | 论坛侧审计也记 login，两边一致 | 密码不入日志已通过代码保证；login 如需脱敏可后续加 |
