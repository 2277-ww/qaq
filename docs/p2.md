# 2 总体约束

本章为强制约束。所有条目标记“必须／禁止”者，不接受实现层面的变通；确因技术原因无法满足时，须走变更流程并同步修订本节。

## 2.1 技术约束

| 编号 | 约束项 | 约束内容 | 验证方式 |
|---|---|---|---|
| TC-01 | 前端框架 | 必须使用 React（函数组件 + Hooks）与 TypeScript，TypeScript 开启 strict 模式，禁止使用 any 逃逸类型检查（确需时须注释说明理由） | 代码评审 + tsconfig 检查 |
| TC-02 | 构建工具 | 必须使用 Vite，构建产物为纯静态资源，可部署于静态服务器或容器 | 构建产物检查 |
| TC-03 | 组件库 | 必须使用 Ant Design 5，主题通过 ConfigProvider 的 design token 定制，禁止直接覆盖组件内部样式类名 | 样式评审 |
| TC-04 | 动效 | 必须使用 GSAP 3 实现页面转场、进度环、数字滚动等动效；动效时长单次不超过 600ms；必须响应 prefers-reduced-motion，开启减少动效时降级为无动画 | 交互走查 |
| TC-05 | 工程独立性 | 必须独立仓库、独立依赖、独立构建、独立部署，禁止与其他平台共享代码包、共用构建流水线或合并为单页应用 | 仓库与流水线核查 |
| TC-06 | 数据访问 | 前端禁止直连任何数据库，禁止在前端代码中出现数据库连接串、密钥；所有数据经服务端接口获取 | 安全扫描 |
| TC-07 | 路由与深链 | 必须支持外部深链进入，课程详情路径形如 `/course/{courseId}`，工坊与考试平台可携带该路径参数跳转，跳转后若未登录须先完成 SSO 再回到该地址 | 联调用例 |
| TC-08 | 环境与配置 | 必须区分开发、测试、生产三套环境，接口地址、客户端标识等通过环境变量注入，禁止硬编码 | 配置检查 |
| TC-09 | 响应式 | 必须支持桌面端与移动端自适应，学生端页面以移动优先设计，最小适配宽度 375px | 多分辨率走查 |
| TC-10 | 浏览器基线 | 支持 Chrome／Edge 100 及以上、Safari 15 及以上、微信内置浏览器（Chromium 86 及以上内核）；不支持 IE 及 Chromium 86 以下内核 | 兼容性测试 |

## 2.2 SSO 登录约束

| 编号 | 约束项 | 约束内容 |
|---|---|---|
| SSO-01 | 唯一身份源 | 论坛为本平台唯一身份提供方。本平台不得自建账号体系，不得提供注册、登录密码、找回密码、修改密码、账号绑定手机号等任何身份相关功能 |
| SSO-02 | 协议 | 必须采用 OIDC 授权码模式并启用 PKCE；协议版本与端点以论坛 SSO 接入说明为准 |
| SSO-03 | 用户标识 | 必须直接使用论坛令牌中的全局 userId 作为本平台全部业务数据的用户外键，不得二次生成用户主键对外暴露 |
| SSO-04 | 角色来源 | 角色必须取自论坛令牌声明，仅接受 student、teacher、admin 三个值；出现未知角色时按 student 降级处理并记录告警，不得报错阻断登录 |
| SSO-05 | 令牌存储 | 访问令牌禁止写入 localStorage；须保存在内存或会话级存储，页面刷新后通过静默续期或重新授权恢复 |
| SSO-06 | 登录态失效 | 接口返回未认证类错误码时，前端须清理本地会话、跳转统一登录页，并携带原始目标地址以便回跳 |
| SSO-07 | 登出 | 本平台登出仅清理本地会话并跳转论坛统一登出；论坛侧发起全局登出后，本平台须在令牌过期或下次请求时失效，不得出现“论坛已登出、本平台仍可操作”的状态 |
| SSO-08 | 鉴权权威 | 前端权限控制仅用于界面呈现，一切数据访问权限以服务端校验为准；服务端必须对每个请求重新校验身份、角色与资源归属 |
| SSO-09 | 越权防护 | 禁止仅凭前端传入的 userId 判定数据归属；服务端必须以令牌中的 userId 为准，忽略或校验请求体中的 userId |
| SSO-10 | 匿名访问 | 全站不提供匿名浏览。未登录用户访问任何业务页面均先跳转 SSO；公开接口不适用本约束，其鉴权见 7.4 |

## 2.3 跨平台联动约束

| 编号 | 约束项 | 约束内容 |
|---|---|---|
| XC-01 | 数据隔离 | 禁止直接访问其他平台的数据库、缓存、消息队列内部主题；禁止跨库联表查询；禁止共享数据表 |
| XC-02 | 联动通道 | 与其他平台的联动仅允许三种方式：SSO 身份传递、公开接口调用、业务事件通知。除此之外不设其他通道 |
| XC-03 | 接口形态 | 对外能力必须以 HTTP 公开接口提供，统一挂在 `/open/v1/` 前缀下，独立于内部接口，独立鉴权、独立限流、独立审计 |
| XC-04 | 出站原则 | 本平台作为数据生产方，只提供查询与事件通知，不主动写入其他平台数据；不代其他平台做业务决策（如判断学生能否进入项目） |
| XC-05 | 入站原则 | 本平台不接受其他平台的写操作，不提供代其他平台修改学习数据的接口；唯一入站数据为 SSO 身份信息与深链跳转参数 |
| XC-06 | 数据库共享禁止 | 任何以“只读账号”“视图”“定时导数”为名义的跨平台数据库直连，同属违规 |
| XC-07 | 页面嵌入 | 禁止以 iframe 方式嵌入其他平台的后台页面，禁止其他平台以 iframe 嵌入本平台业务页作为其功能模块 |
| XC-08 | 降级要求 | 公开接口或事件通道异常不得阻断本平台主流程（学习、发布）；异常须可观测（监控指标 + 告警），由消费方决定其降级策略 |
| XC-09 | 变更通知 | 公开接口与事件契约的破坏性变更须提前一个版本周期通知全部订阅方，并保留旧版本至少一个学期 |
| XC-10 | 调用登记 | 每个调用本平台公开接口的外部平台须单独登记客户端凭证与授权范围，禁止共用凭证 |

## 2.4 数据规范约束

### 2.4.1 响应结构

全部接口（内部与公开）必须返回统一包裹结构，不得直接返回裸数组或裸对象。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| code | number | 是 | 业务状态码，0 表示成功，非 0 表示业务失败 |
| message | string | 是 | 结果描述，成功时固定为 OK，失败时为可直接展示的中文提示 |
| data | object | 否 | 业务数据，失败时可为空对象 |
| requestId | string | 是 | 服务端生成的请求追踪标识，用于日志关联与问题定位 |
| timestamp | string | 是 | 服务端响应时间，ISO8601 带时区 |

### 2.4.2 分页规范

| 约束项 | 规定 |
|---|---|
| 请求参数 | page（页码，从 1 开始）、pageSize（每页条数，默认 10，最大 100） |
| 响应字段 | data 内固定包含 page、pageSize、total、totalPages、list 五个字段 |
| 排序 | 默认按业务时间倒序；支持的排序字段须在接口文档中逐一列出，禁止任意字段排序 |
| 越界处理 | 页码超过总页数时返回空列表，不报错 |
| 深分页 | total 超过 10000 时，公开接口须使用游标分页替代页码分页，并在接口说明中标注 |

### 2.4.3 错误码

| 约束项 | 规定 |
|---|---|
| 分段 | 0 为成功；4xxxx 为客户端类错误；5xxxx 为服务端类错误；业务码段按模块划分，同一码不复用 |
| 唯一性 | 一个错误码只表达一种失败原因，禁止一个码承载多种语义 |
| 消息 | message 面向终端用户可读，不得暴露堆栈、SQL、内部表名 |
| 定位 | 客户端错误须同时返回 requestId，便于用户反馈时定位 |
| 透传 | 本平台不得透传其他平台的错误码，须转换为本平台错误码并保留上游信息于日志 |

### 2.4.4 时间规范

| 约束项 | 规定 |
|---|---|
| 格式 | 全部时间字段使用 ISO8601 扩展格式并携带时区偏移，形如 2026-11-03T11:52:16+08:00 |
| 时区 | 统一使用 Asia/Shanghai（+08:00），服务端存储为 UTC，输出时转换 |
| 精度 | 秒级为准；需要毫秒精度的事件字段须在字段说明中明示 |
| 禁止 | 禁止使用时间戳数字、禁止使用无时区的本地时间字符串、禁止使用 2026/11/03 这类非标准格式 |
| 日期 | 纯日期字段（如开课日期）使用 YYYY-MM-DD |

### 2.4.5 状态与枚举编码

| 约束项 | 规定 |
|---|---|
| 命名 | 状态值一律使用大写蛇形命名，如 DRAFT、PENDING_REVIEW、PUBLISHED |
| 口径 | 存储值、接口值、前端展示映射三者一致，前端不得自定义另一套状态字符串 |
| 展示 | 中文展示文案由前端字典统一映射，禁止在接口中返回中文字状态 |
| 扩展 | 新增状态须同时更新状态机、字典与本文档附录 A，禁止使用未登记的状态值 |

### 2.4.6 标识与文本

| 约束项 | 规定 |
|---|---|
| 主键 | 业务主键为 26 位 ULID 字符串，对外作为不透明标识使用；禁止在接口中暴露自增数字主键 |
| 用户标识 | 一律使用论坛全局 userId，长度按论坛约定，本平台不做截断 |
| 编码 | 全部文本使用 UTF-8；禁止在接口中出现 GBK 编码内容 |
| 长度 | 标题不超过 120 字符，摘要不超过 500 字符，笔记正文不超过 20000 字符，超出须在接口层拒绝并返回参数错误 |
| 富文本 | 图文内容为受限 HTML，仅允许白名单标签与属性，入库前须做服务端净化 |
| 空值 | 无值字段统一返回 null，禁止返回空字符串或 “undefined” 占位 |

### 2.4.7 业务事件格式

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| eventId | string | 是 | 事件唯一标识，ULID，消费方据此幂等 |
| eventType | string | 是 | 事件类型，格式为 领域.动作过去式，如 course.completed |
| eventVersion | string | 是 | 事件契约版本，形如 1.0；字段增删须升版本 |
| occurredAt | string | 是 | 事件发生时间，ISO8601 带时区 |
| sourcePlatform | string | 是 | 生产方平台编码，本平台为 selfstudy |
| producer | string | 是 | 生产服务标识 |
| userId | string | 是 | 事件主体用户的全局标识 |
| traceId | string | 是 | 链路追踪标识，与产生该事件的请求同源 |
| data | object | 是 | 事件载荷，按事件类型定义，只承载事实，不承载指令 |

事件通用规则：至少一次投递；消费方须按 eventId 幂等；事件不保证顺序，涉及顺序的消费方须按 occurredAt 自行排序；单条事件载荷不超过 16KB，超出部分以标识引用替代。

### 2.5.2 边界红线

以下行为视为越界，评审阶段一票否决：

1. 在自学平台内出现考试、测验、判卷、成绩、排名相关字段或页面；
2. 在自学平台内出现项目、任务、审批、成员、排期等工坊业务对象；
3. 为“方便工坊判断”而在本平台保存 projectId、项目成员关系或准入结论；
4. 提供任何写接口供其他平台修改学习进度或完成状态；
5. 以接口聚合为名直接读取考试平台成绩或工坊项目数据并展示；
6. 将课程完成状态直接解释为“通过考核”或“具备上岗资格”；
7. 在本平台内实现角色自定义、权限组配置等身份管理能力；
8. 以 iframe 或脚本注入方式把本平台页面嵌入其他平台充当模块。
