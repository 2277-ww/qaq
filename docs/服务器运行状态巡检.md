## 2　发现的问题

### P1　WebSocket 地址指向 127.0.0.1（无效配置，当前不触发）

**现象**：页面源码里 `url: 'wss://127.0.0.1/wss'`。

**原因**：`config/config.php` 第 158 行仍是部署默认值

```php
$config['websocket']['connect_address'] = '127.0.0.1:8282';
```

`Home/Controllers/Controller.php::getWebsocketInfo()` 在 HTTPS 下只取地址的域名部分再拼路径：

```php
list($domain) = explode(':', $websocket->connect_address);
$websocket->connect_url = sprintf('wss://%s/wss', $domain);
```

于是 `partials/js_vars.volt` 把 `window.websocket.connect_url` 注入成 `wss://127.0.0.1/wss`。一旦有代码去连接，访客的浏览器就会尝试连接**访问者自己的电脑**，必然失败。

**为什么当前不影响运行**（逐条核实）：

| 核实项 | 结果 |
|---|---|
| 全站哪个脚本会 `new WebSocket` | 只有 `public/static/home/js/chapter.live.chat.js` 一处 |
| 该脚本被哪个模板引用 | 只有 `chapter/live/active.volt`（直播章节） |
| 章节页是否加载它 | 不加载（`/chapter/2` 的 script 清单里没有） |
| 全站直播数据 | `kg_chapter_live` **0 行** |
| `/live/*` 路由 | 全部 404（控制器只有 chats/stats/status/bindUser/sendMessage，无 index/list） |
| 导航是否有直播入口 | 无 |

也就是说：没有任何线上页面会实例化 WebSocket 连接，这只是把地址写到了全局变量里而无人使用，浏览器控制台不会报错，私信与通知也不走这条链路（它们走普通 HTTP 请求）。

**这是隐患而非故障**：将来若真的开直播（往 `kg_chapter_live` 插入数据），聊天室会立刻连不上。届时要同时补齐三步：

```bash
# 1. 启动 GatewayWorker
cd /www/ctc/websocket && php start.php start -d

# 2. nginx 443 server 增加代理
location ^~ /wss {
    proxy_pass http://127.0.0.1:8282;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
    proxy_read_timeout 3600s;
}

# 3. 改正地址为 8.138.34.151:8282
```

内存余量约 800M，GatewayWorker（1 register + 1 gateway + 4 business）约占 80–120M，可以跑，但需要 systemd 守护。

### P2　后台密码在 09:54 被重置且未留存（已修复）

**现象**：`https://8.138.34.151/admin/video_upload/` 用 2026-11-05 09:11 记录的密码访问返回 401。

**原因**：`/etc/nginx/.htpasswd-ctc` 的修改时间是 `2026-11-05 09:54:07`，说明期间执行过一次 `10_harden.sh --reset-pass`（或等价命令）。该脚本只在终端打印一次新密码，不落盘，所以覆盖后原密码立即失效；nginx 日志在 09:54:13 还记录了一条 `user "admin": password mismatch`，说明改完之后又用错误的密码试过一次。

**处理**：已重新生成密码，并把结果写入只有 root 可读的 `/root/ctc_admin_pass.txt`（新脚本 `deploy/server/cert/reset_admin_pass.sh`）。验证结果：正确凭据 200、错误凭据 401、无凭据 401。

顺带修掉一个脚本缺陷：原写法用 `tr -dc ... | head -c 14` 取随机串，`head` 提前关闭管道让 `tr` 收到 SIGPIPE，在 `set -euo pipefail` 下脚本会静默中止（第一次执行没有任何输出、也没改文件）。现已改为 `openssl rand -hex 7`。
