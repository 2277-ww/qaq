## 3　环境清单与选型理由

| 组件 | 版本 | 为什么是这个版本 |
|---|---|---|
| PHP | 7.3.33 | `composer.json` 要求 `ext-phalcon ~3.4`，Phalcon 3.4 最高只支持到 PHP 7.3；上 7.4 必须升 Phalcon 4，93 个控制器全部要改 |
| Phalcon | 3.4.5 | composer 装不了，必须源码编译（见 §5 坑 3） |
| MariaDB | 10.5.29 | 1.87 GB 内存装 MySQL 8 会被 OOM；MariaDB 10.5 与本地开发库 MySQL 5.7 语义最接近，导出文件可直接导入 |
| Redis | 6.2.24 | 会话与缓存后端，应用硬依赖 `ext-redis` |
| nginx | 1.24 | 系统已有，新增独立 server 块 |
| PHP 扩展 | phalcon / redis 5.3.7 / igbinary 3.2.15 / pdo_mysql / gd / mbstring / opcache / zip / bcmath | 前三个需编译，其余走包管理 |

来源：PHP 与依赖包来自 **remi-php73 仓库的阿里云镜像**（`mirrors.aliyun.com/remi/`）；官方 `rpms.remirepo.net` 在本机出口只有 20–30 KB/s，实测拉元数据会卡死 5 分钟以上。

## 5　踩坑记录（都可复现，写下来备查）

**坑 1：remi 源装不上**
`remi-release-8.rpm` 依赖虚拟包 `system-release(releasever) = 8`，Alinux 3 不提供。
→ 改 `rpm -ivh --nodeps`，并把仓库文件里 `$releasever` 硬改成 `8`。

**坑 2：装成了 PHP 7.4**
remi 主仓（`remi.repo`）在 EL8 上默认就是 PHP 7.4，且 Alinux 自带源里也有 `php-common-7.4`，`dnf install php-fpm` 会解析到 7.4 并与之冲突。
→ 手写 `remi-php73.repo`（`baseurl` 指向 php73 目录），并给 AliYun.repo / epel 全部加 `exclude=php php-*`，让 PHP 只能从 php73 仓取。

**坑 3：Phalcon 编译被 OOM 杀掉**
`gcc: fatal error: Killed signal terminated program cc1`。`phalcon.zep.c` 是单个巨型编译单元，`-O2` 下 cc1 峰值 1.2 GB+，1.87 GB 内存（含 600 MB 的 Halo Java 进程）扛不住。
→ 加 4 GB swap，并把编译参数降到 `-O1 -fno-var-tracking`，单线程编译约 6 分钟通过。

**坑 4：`unzip` 不存在**
Alinux 最小化安装没带，`unzip: command not found`。
→ `dnf install -y unzip`。

**坑 5：500 但没有任何日志**
现象：首页 500、0 字节、php-fpm 日志无记录。
根因有两层：① 打包产物里 `config/config.php` 权限是 600（继承模板），apache 读不了；② 修好权限后又 500，因为 `storage/log/` 里存在 **root** 身份创建的同名日志文件（644），apache 无法追加，`Phalcon\Logger` 抛异常，而错误处理器自身又要写日志 → 死循环，最终静默 255 退出。
→ `chmod 644 config.php`；`chown -R apache:apache storage` 并把文件统一 664、目录 775。**教训：不要用 root 跑一次 CLI 再去调 FPM**，之后所有验证都用 `su -s /bin/sh apache`。

**坑 6：本地 Git Bash 把远端路径改写**
`python remote.py put ./x /root/x` 报 `No such file or directory`，实际是 MSYS 把 `/root/x` 转成了 `C:/.../root/x`。
→ 调用前加 `MSYS_NO_PATHCONV=1`。同时 paramiko 的 SFTP 子系统在这台服务器上不可用，改为 `cat > file` 走 stdin 传输，69 MB 包约 37 秒。

## 8　尚未完成 / 已知限制

1. **外网 8080 未放行**（唯一阻塞项）。需在阿里云控制台 → 安全组 → 入方向添加：协议 TCP、端口 8080、授权对象 `0.0.0.0/0`。
2. **演示视频缺失**。打包时剔除了 1.3 GB 的 `public/static/vod`，课程里的点播视频会 404。要恢复需单独上传视频或接对象存储 + CDN。
3. **直播聊天不可用**。`chapter.live.chat.js` 会连 `ws://127.0.0.1:8282`，需要 `websocket/start.php` 常驻进程 + 放行 8282，目前未启动。普通课程页不受影响。
4. **HTTPS 未配置**。当前是 `http://IP:8080`。要上 HTTPS 需要一个域名（证书无法签发给纯 IP，除非用 IP 证书）。
5. **root 密码强度不足**，且已在对话中明文传递。建议 `passwd` 改掉，并考虑禁用密码登录、改用密钥。
6. 定时任务、消息队列等常驻进程（`scheduler.php`）未配置，目前不影响前台浏览。

## 9　与 Vercel 方案的关系

此前的结论（`docs/源码核查与Vercel部署可行性.md` 第 5 节）依然成立：Vercel 的 Serverless 与 Container 运行时都跑不了这套 PHP 7.3 + Phalcon 3.4 的常驻应用。本次在真实服务器上把环境跑通，反过来验证了当时的判断——**缺的是 PHP 7.3 运行时、可写磁盘和常驻服务，换平台解决不了，只能换承载形态**。
