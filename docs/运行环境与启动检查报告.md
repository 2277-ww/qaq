## 4　问题清单与修复建议

### P1-1　内存预算贴着上限

**证据**：Halo（Java）RSS **612 MB**，堆上限 `-Xmx900m`；php-fpm 10 子进程 × 43 MB ≈ **430 MB**；mysqld ≈ 300 MB（含 128 MB buffer pool）；nginx + 各类 agent ≈ 120 MB。峰值叠加已接近 1870 MB，而 `ffmpeg` 转码瞬时还要 300–600 MB。

**失效表现**：上传大视频触发转码时，php-fpm 子进程可能被 OOM Killer 杀掉，表现为 502/白屏；swap 已有 245 MB 占用，说明已经在换页。

**修复建议**（任选 2–3 条即可明显缓解）：

```bash
# ① 压低 Halo 堆上限（编辑其启动脚本后重启 Halo）
-Xms256m -Xmx900m  →  -Xms256m -Xmx512m

# ② php-fpm 子进程收到 8
sed -i 's/^pm.max_children = 10/pm.max_children = 8/' /etc/php-fpm.d/www.conf
systemctl reload php-fpm

# ③ 转码降优先级，避免抢占前台请求
#    08 转码脚本里 ffmpeg 前加：nice -n 15 ionice -c3
```

### P1-2　Redis 无内存上限且不淘汰

**证据**：`maxmemory 0`、`maxmemory-policy noeviction`。当前仅用 1.35 MB，短期无虞；一旦缓存条目暴涨（注解 + 元数据 + 业务列表缓存），Redis 会拒绝写入并返回 OOM 错误，表现为页面报错而非变慢。

**修复建议**：

```bash
redis-cli config set maxmemory 256mb
redis-cli config set maxmemory-policy allkeys-lru
# 持久化：写入 /etc/redis.conf 同名两行，再 systemctl restart redis
```

> 注解缓存在 Redis 里（`_PHCR_ANNOTATION_*`），被淘汰后会自动重建，代价是首请求变慢，不会报错。

### P1-3　备份的 03:30 自动执行尚未实证

**证据**：`/var/log/cron` 记录 `2026-11-04 17:34 (CRON) bad command (/etc/cron.d/ctc-backup)`，当时 cron 文件格式非法；11-05 09:12 重载后格式已正确（`cat -A` 校验通过），但下一次 03:30 是 11-06，尚无记录。现有的 4 个 dump 全是手工触发。

**验证方法**：11-06 上午执行

```bash
cat /www/backup/backup.log | tail -3     # 应出现 2026-11-06 03:3x backup ok
ls -l /www/backup/ctc-20261106-*.sql.gz  # 应有当日 dump
```

**修复建议**：若仍无记录，把该行改成显式调用并加日志：

```cron
30 3 * * * root /bin/bash -lc '/usr/local/bin/ctc-backup.sh >> /www/backup/cron.log 2>&1'
```

### P2-1　未启用 gzip

站点与全局配置里没有任何 `gzip` 指令，`theme-police.css`（25 KB）原样传输。首屏有十余个 CSS/JS，压缩后可省 60–70% 流量，弱网提升明显。

```nginx
# /etc/nginx/nginx.conf 的 http 块内
gzip on;
gzip_comp_level 5;
gzip_min_length 1k;
gzip_types text/plain text/css application/javascript application/json image/svg+xml;
gzip_vary on;
```

### P2-2　缺安全响应头

当前无 `Strict-Transport-Security`、`X-Frame-Options`、全局 `X-Content-Type-Options`（仅 `/media/vod/` 有）。建议在 443 server 块内统一加：

```nginx
add_header Strict-Transport-Security "max-age=31536000" always;
add_header X-Frame-Options "SAMEORIGIN" always;
add_header X-Content-Type-Options "nosniff" always;
add_header Referrer-Policy "strict-origin-when-cross-origin" always;
```

### P2-3　PHP 7.3 已 EOL

7.3 自 2021-12 起停止安全维护，且 Phalcon 3.4.5 只支持到 7.3/7.4。短期不影响运行，但属于长期风险；升级需同时评估 Phalcon 4/5 的 API 变更，建议单独立项，不要与当前功能迭代混做。

### P2-4　证书续期窗口临近

`days_left=7`、`not_after=Nov 11 16:02:41 2026`，看门狗在 11-08 进入 T-3 窗口时才会 `acme.sh --cron --force`。**11-08 与 11-09 需各看一次** `https://8.138.34.151/_status/cert.txt`，确认 `last_renew` 不再是 `skipped`。

### P3-1　nginx 重复 default server 警告

`conflicting server name "_" on 0.0.0.0:80` —— 80 端口有两处 `default_server`。当前行为确定（plaza.conf 生效），但将来绑定域名时容易踩坑，建议合并为一个 default server。

### P3-2　日志属主混用

`storage/log/console-*.log` 为 `root:root`（CLI 与 cron 产生），`http-*.log` 为 `apache:apache`。目前互不干扰，但排查问题时容易误判"没有写权限"。建议在 `clean_log` 后统一 `chown apache:apache`。

### P3-3　安全基线

root 仍使用弱密码且密码登录开启、无 fail2ban、无主机防火墙（仅靠安全组）。这三项与"能否运行"无关，但决定了"能安全运行多久"。
