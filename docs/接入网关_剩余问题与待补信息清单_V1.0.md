## 2. 为什么上一版「16 项全过」仍漏掉了 E1 / E4

上一版验收覆盖了登录链路（GET/POST/错误密码/限流/建号）与 401 系列拒绝用例，但：

1. **没测握手接口**——它是对端接入第一步，也是唯一会走到 `getConfig()` 的路径；
2. **把 403 当成功**——`passed = status != 401`，服务态被 `assertReadable` 挡在业务层之外照样亮绿灯；
3. **只测无 internal 的路径**——网关实际使用的 `/internal/*` 从未进过验收。

这三点合起来造成「验签全绿、入站却一个业务接口都调不通」。现已全部纳入正式脚本。

### 3.3 建议确认（不阻塞当前功能）

- 论坛 `role` 的**取值全集**：现实现 `admin` 不提权、`teacher → edu_role=2`、其余按学员。若有 `moderator`、`auditor` 等角色，需明确映射。
- **停用账号策略**：`40104` 的两种 reason 已在 `AccountVerify` 中按响应体 `data.reason` 区分（`invalid_credentials` 让用户重试 / `account_unavailable` 联系管理员），请确认论坛侧确实按文档返回。
- **网关 429 退避**：平台侧限流 10 次/60s/IP，网关侧 200 QPS/AppKey + 60 QPS/IP；`Retry-After` 是否透传。
- **账号换绑/合并**：`forum_uid` 有唯一索引，并发首次登录已做冲突回查；若论坛 uid 发生变更或需要合并两个本地账号，需另定规则。
