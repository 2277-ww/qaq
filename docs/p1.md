# 1 文档概述

## 1.1 项目背景

警院 WeChat 全生态由五个相互独立、独立部署的业务平台共同构成：论坛、自学平台、考试平台、实训工坊、成果展示广场。五个平台不合并工程、不共享代码仓库、不共用数据库，通过统一身份、公开接口与业务事件三条通道完成生态级联动。论坛作为唯一身份源，为其余四个平台提供 OIDC／OAuth2.1 单点登录能力。

在自学平台立项之前，警院的技术类课程资源与警务业务知识资源长期处于碎片化状态，主要问题集中在四个方面：

1. **资源分散，检索成本高**。课程视频、操作手册、图文教程散落于微信群文件、个人网盘、公众号推文与教师本地磁盘，学生无法形成稳定的学习入口，同一份资料在不同年级反复转发、版本失控。
2. **学习过程不可见**。资源是否被打开、看了多少、卡在第几节，均无采集手段。教师无法判断“讲过”与“学会”之间的差距，教研室也无法评估资源建设投入的实际效果。
3. **实训准入缺少客观基线**。实训工坊以项目制方式组织教学，项目开始前要求学生具备相应的工具链与知识准备（如 Docker 部署、YOLO 视觉环境搭建）。此前依赖教师口头确认或课前临时补课，准入判断缺少可核验的、来自系统的完成状态依据。
4. **学习成果无法沉淀**。学生在各平台产生的学习行为彼此隔离，无法汇聚为贯穿在校期间的个人成长记录，评优、推免、技能认证等场景缺少过程性数据支撑。

自学平台即为解决上述问题而建设：把分散的学习资源收敛为结构化课程，把学习行为转化为可查询的进度数据，把“是否具备前置能力”转化为可由其他平台直接调用的完成状态，并把学习数据归集到全局个人成长档案。

## 1.2 平台定位

### 1.2.1 一句话定位

自学平台是警院 WeChat 全生态中**面向学生的实训前置学习资源平台**，承担“学”的环节，向上承接统一身份，向下为考试平台、实训工坊、成果展示广场与全局个人成长档案提供课程与学习数据。

### 1.2.2 在生态中的位置

| 关系 | 对方平台 | 交互内容 | 通道 |
|---|---|---|---|
| 上游依赖 | 论坛 | 用户身份、角色声明、登录态、全局登出 | OIDC／OAuth2.1 SSO |
| 下游服务 | 考试平台 | 用户课程完成状态（作为报考或参考的前置校验） | 公开接口 |
| 下游服务 | 实训工坊 | 课程目录、课程完成状态（作为项目前置必修校验） | 公开接口 + 业务事件 |
| 下游服务 | 成果展示广场 | 课程完成事实（作为学习成果展示的数据来源之一） | 业务事件 |
| 下游服务 | 全局个人成长档案 | 学习记录汇总（课程数、完成数、学习时长、分类分布） | 公开接口 + 业务事件 |
| 平行关系 | 考试平台、实训工坊、成果展示广场 | 无直接数据依赖，不互访数据库 | — |

### 1.2.3 平台不做的事

平台边界是本文件的强制约束。以下能力明确不属于自学平台，任何迭代不得以“顺手支持”为由纳入：

- 不承载考试、测验、判卷、成绩、补考、证书发放；
- 不承载实训项目的立项、审批、任务分派、过程管理、成员管理与结项评价；
- 不承载成果展示、作品点赞、评优投票；
- 不承载论坛帖子、评论、私信等社区能力；
- 不自建账号体系，不提供注册、密码、找回密码、账号冻结等身份管理能力；
- 不承担统一文件存储职责，仅保存资源引用标识，实际文件由统一文件服务托管。

## 1.3 文档目的

本文档是自学平台的需求基线，用于：

1. 向业务方（教务处、教研室、实训中心）确认平台能力范围与流程规则，形成书面共识；
2. 作为 UI 设计、前端开发、服务端开发、测试用例设计的唯一需求依据；
3. 作为与论坛、考试平台、实训工坊、成果展示广场进行跨平台联调的接口与事件契约依据；
4. 作为验收测试与需求变更控制的基准版本。文档中标注编号的需求条目（FR-、OPEN-、EVT-、NFR-）均为可独立验收的最小单元，变更须走变更记录。

## 1.4 文档范围

### 1.4.1 范围内

| 序号 | 范围项 | 说明 |
|---|---|---|
| 1 | 课程分类体系 | 七大类固定分类及管理员可维护的分类字典 |
| 2 | 课程内容生产 | 教师创建课程、编排章节、编写图文、上传视频、提交审核 |
| 3 | 内容审核与发布 | 草稿、待审核、已发布、已归档全状态管理与审核留痕 |
| 4 | 学习过程 | 图文阅读与视频观看的进度采集、进度合并、完成判定 |
| 5 | 学习工具 | 课程收藏、个人学习笔记、我的学习 |
| 6 | 对外能力 | 课程与完成状态的公开查询接口、course.completed 业务事件 |
| 7 | 数据归集 | 学习记录按统一 userId 汇总，供全局个人成长档案消费 |

### 1.4.2 范围外

| 序号 | 排除项 | 归属平台 | 说明 |
|---|---|---|---|
| 1 | 考试组织与判卷 | 考试平台 | 本平台仅提供完成状态，不参与任何考核判定 |
| 2 | 项目立项与审批 | 实训工坊 | 本平台不感知项目、不存 projectId |
| 3 | 项目过程与成员管理 | 实训工坊 | 本平台不提供任务、排期、成员名册 |
| 4 | 成果展示与评价 | 成果展示广场 | 本平台仅抛出完成事实 |
| 5 | 帖子、评论、问答 | 论坛 | 课程不设讨论区 |
| 6 | 文件存储与转码基础设施 | 统一文件服务 | 本平台仅登记引用与转码状态 |
| 7 | 身份与角色管理 | 论坛 | 本平台只读角色声明 |

### 1.4.3 本期不实现（后续版本候选）

课程评论与问答、直播授课、学习证书生成、基于学习行为的智能推荐、课程学习排行榜、笔记导出与分享。上述能力如后续提出，须先确认归属平台与边界，再单独评审。

## 1.5 术语与缩略语

| 术语 | 英文／缩写 | 说明 |
|---|---|---|
| 单点登录 | SSO | 由论坛统一认证，其余平台不重复校验密码 |
| 身份提供方 | IdP | 本生态中指论坛 |
| 开放授权 | OAuth2.1／OIDC | 论坛对外提供的授权与身份协议，采用授权码 + PKCE |
| 全局用户标识 | userId | 论坛签发的全局唯一用户标识，全生态一致，本平台不自造用户 ID |
| 课程 | Course | 学习资源的最小交付单元，含若干章节与课时 |
| 章节 | Chapter | 课程的逻辑分组，仅用于组织课时 |
| 课时 | Lesson | 学习的最小单元，类型为图文或视频 |
| 进度覆盖率 | coverage | 视频已观看区间占视频总时长的比例，用于完成判定 |
| 课程完成 | Completion | 课程内全部已发布课时均达完成标准的状态 |
| 前置必修 | Prerequisite | 由实训工坊在自身侧绑定、要求学生先修完的课程 |
| 业务事件 | Business Event | 跨平台异步通知报文，格式遵循约束规范 |
| 公开接口 | Open API | 面向其他平台开放、经客户端凭证鉴权的只读接口 |
| 投影表 | Projection | 为对外高频查询预先聚合的宽表，非业务主数据 |
| 个人成长档案 | Growth Profile | 全生态汇聚的学习与成长记录，本平台为数据生产方之一 |
| 课程版本 | courseVersion | 课程内容每次发布产生的递增版本号，用于完成判定的基线锁定 |

## 1.6 角色说明

本平台仅设三类角色，角色编码固定为 `student`、`teacher`、`admin`，由论坛在令牌中声明，本平台不新增、不派生、不允许后台自定义角色。

| 角色编码 | 名称 | 来源 | 核心职责 | 权限边界 |
|---|---|---|---|---|
| student | 学生 | 论坛角色声明 | 浏览课程、学习、收藏、记笔记、查看自身进度 | 仅可见与操作自身数据，不可见他人笔记与进度明细 |
| teacher | 教师 | 论坛角色声明 | 创建与维护本人课程、编排内容、提交审核、查看本人课程统计 | 仅可操作本人作为责任教师的课程，不可审核、不可改分类 |
| admin | 管理员 | 论坛角色声明 | 分类管理、内容审核、归档审批、违规处置、看板与审计、开放接口客户端管理 | 可审核全部课程，不可代替教师编写课程内容 |

除上述三类业务角色外，系统还存在以下**非登录角色**，仅用于接口与事件的调用方识别，不参与页面权限：

| 角色 | 标识 | 说明 |
|---|---|---|
| 外部平台 | client | 经客户端凭证鉴权调用公开接口的考试平台、实训工坊、档案服务等 |
| 事件订阅方 | subscriber | 订阅业务事件的平台，须在事件总线登记回调地址 |
| 系统任务 | system | 定时任务、转码回调、事件重投等内部主体，操作须留审计 |

一名用户可同时具备多个角色（如教师兼任管理员），权限判定取最高角色，但**业务数据归属不因角色叠加而扩大**：管理员身份不使其自动成为任何课程的责任教师。
