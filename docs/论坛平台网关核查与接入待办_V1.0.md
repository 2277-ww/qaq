> 核查时间：2026-11-05 23:18—23:35
> 关联文档：`docs/学习进度多平台对接实现说明_V1.0.md`（对端注册表与出站契约）

## 2 两个必须解决的问题

### P1 假成功：兜底路由把「没配上」伪装成「成功」

APISIX 存在一条兜底路由（形如 `/*`），任何未匹配的路径都返回 **200 + 默认页 HTML**。

对本平台的直接影响：投递器拿到的状态码是 200，若只看状态码就会判定「已推送」，事件置为 `status=1` 且不再重试。实际论坛平台一个字节都没收到，**监控、页面、统计全部显示正常**，属于最难发现的一类故障。

实测复现（未修复前）：

```
peer sync: sent=2 failed=0 dead=0 [forum:2]      ← 看起来完全成功
kg_exam_outbox: status=1, response_code=200
实际对端：0 条入库
```

### P2 统一鉴权拦截服务态调用

`/api/v1/learning/*` 与 `/api/v1/exam/learning/progress` 都要求 `Authorization: Bearer`。而本平台的跨平台调用是**服务态**模式，凭据是 `X-Internal-Sign`（HMAC-SHA256）+ `X-App-Code`，不带用户令牌。

现在的后果：一旦把 `gateway.base_uri` 指向这台网关，所有投递都会拿到 401。按原逻辑 401 属于 4xx 契约错误，会**直接进死信**，历史事件一次性全废。

## 3 已完成的代码修复（本平台侧）

| # | 改动 | 位置 | 效果 |
| --- | --- | --- | --- |
| 1 | 2xx 响应必须可信才算成功 | `Gateway::isAcceptableResponse()` | 空响应放行；`{`/`[` 开头放行；HTML 兜底页判失败 |
| 2 | 新增 `gateway.expect_json` | `config/config.php` | 默认 `true`，可对返回纯文本的对端关闭 |
| 3 | 新增 `gateway.access_token` | 同上 | 网关要求 Bearer 时配置，自动带 `Authorization` |
| 4 | 429 / 408 转为可重试 | `Sync::flush()` | 限流与超时不再直接死信 |
| 5 | 对端级网关地址 | `Peers::baseUri()` + `gateway.getBaseUri($peer)` | 论坛平台可用独立网关，不影响考试平台 |

修复后实测（同一路径、同一事件）：

```
peer sync: sent=0 failed=2 dead=0 [forum:2]        ← 不再假成功
kg_exam_outbox: status=2, response_code=200
last_error: gateway_returned_non_json:You need to enable JavaScript to run this app...
```

保留原始 200 便于排障，同时错误信息直接指向「网关返回了非 JSON」，不会让人误以为是业务字段对不上。事件进入退避重试（1s/5s/30s/2min/10min/1h），网关配置修好后自动补发，不需要人工重放。

## 4 需要网关方完成的配置

以下四项缺一不可，建议按顺序做。

### 4.1 兜底路由不能再返回 200

两种处理，选其一：

- **推荐**：删除 `uri: /*` 的兜底路由，让未配置路径回到 APISIX 原生 404；
- 或者保留但把上游换成固定返回 404 的服务。

验证方式（任意一个不存在的路径都必须不是 2xx）：

```bash
curl -s -o /dev/null -w '%{http_code}\n' http://8.138.246.181/random_nonexist_123   # 应为 404
```

### 4.2 补齐三条业务路由

| 路由 | 上游 | 说明 |
| --- | --- | --- |
| `/api/v1/forum/learning/progress` | 论坛平台后端 | 接收本平台推送的 `course.completed` |
| `/api/v1/exam/learning/*` | 考试平台后端 | 路径以考试平台契约为准 |
| `/api/v1/learning/*` | `https://8.138.34.151` | **反向**：本平台接收回执、拉取、重放 |

第三条最容易被漏。本平台的回执接口 `/api/v1/learning/peers/exam/receipts`、拉取 `/pull`、重放 `/replay` 都是**对端回调本平台**，网关若只配出站方向，这三个接口永远不会被调用。

上游是 HTTPS 且证书为自签时，需要在节点级关闭校验，否则表现为握手失败（日志里容易被误读成「自学平台接口挂了」）：

```json
"upstream": {
  "type": "roundrobin",
  "scheme": "https",
  "pass_host": "node",
  "tls": { "verify": false },
  "nodes": { "8.138.34.151:443": 1 }
}
```

### 4.3 `/api/v1/learning/*` 改注入可信头，去掉 jwt

按《统一身份与网关接入说明》，可信头必须由网关注入，不能让调用方自带——否则任何人都能伪造 `X-User-Id` 冒充他人。

这条路由需要：**移除 jwt-auth / key-auth 插件**，改用 `proxy-rewrite` 或 `serverless-pre-function` 注入：

| 头 | 取值 |
| --- | --- |
| `X-User-Id` | 目标用户对外主键（OIDC `sub`） |
| `X-Auth-Mode` | `service`（平台间调用）或 `user` |
| `X-Timestamp` | 当前 Unix 秒；本平台校验偏移 ≤ 300 秒 |
| `X-Request-Id` | 网关生成的请求编号，用于全链路反查 |

`X-Internal-Sign` 由调用方计算、网关原样透传，不需要网关重算。APISIX 默认透传自定义头，`Idempotency-Key` 也会原样到达。

> 具体插件字段以网关实际部署为准，建议先用 `GET /apisix/admin/routes` 导出既有配置再改，避免覆盖他人的路由。

### 4.4 限流要给内部服务留配额

当前是通用限流（60 次/窗口）。本平台 `exam_sync` 每 3 分钟一轮、单轮最多 200 条，瞬时可能超过通用配额，触发 429。

要求：内部服务用独立 consumer 单独计配额，或把服务态调用的配额提高到能覆盖单轮批量。本平台侧已把 429 改为可重试，但频繁 429 会让同步延迟累积，仍应在网关侧配好。

## 5 联调验收顺序

不要一次性切换，按这四步走，每步都能单独回退。

```bash
# 第一步：只用本机命令行验证网关行为，不动生产配置
curl -s -o /dev/null -w '%{http_code}\n' http://8.138.246.181/random_nonexist_123      # 期望 404
curl -s -X POST http://8.138.246.181/api/v1/forum/learning/progress -d '{}' -D -         # 期望 401/422，不能是 200+HTML

# 第二步：论坛对端保持关闭，仅确认 endpint 拼接正确
curl -s https://8.138.34.151/api/v1/learning/peers | grep -o '"endpoint":"[^"]*forum[^"]*"'

# 第三步：临时启用论坛对端，单条事件试投
cd /www/ctc && php console.php peer_reconcile main forum && php console.php exam_sync main

# 第四步：核对状态与对端入库
mysql -uctc -p*** ctc -e "SELECT id,target,status,response_code,last_error FROM kg_exam_outbox WHERE target='forum';"
```

判定标准：

| 结果 | 含义 |
| --- | --- |
| `status=1` 且对端确有数据 | 接通 |
| `status=1` 但对端无数据 | **假成功未修好**，回到 4.1 |
| `status=3` + `HTTP 401` | 鉴权未放行，回到 4.3 |
| `status=2` + `HTTP 429` | 限流，回到 4.4 |
| `status=2` + `gateway_returned_non_json` | 路由未配或上游返回错误页，回到 4.1/4.2 |

## 6 遗留风险

1. **80 端口明文**：`X-Internal-Sign` 是 HMAC 签名，只能证明未被篡改，不能防窃听；学号、课程、进度都在明文 payload 里。生产必须开 443 上证书。
2. **管理面在内网**：9180 未对外开放是对的，但也意味着路由变更只能登录服务器操作，需要确认谁持有 admin key，以及变更是否有记录。
3. **兜底 200 若保留在线上**：任何未接入的新路径都会被判「成功」，这不是本平台能单方面兜住的风险，必须在网关层消除。
4. **对端单号语义未定**：`remote_id` 目前按考试平台成绩单编号设计，论坛侧若用帖子号，需要在对接文档里写清字段含义。
