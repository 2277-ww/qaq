## 2　后台鉴权

### 2.1 凭据

```
地址：https://8.138.34.151/admin/video_upload/
用户：admin
密码：<见服务器 /etc/nginx/.htpasswd-ctc 或你的密码管理器>
```

密码是首次执行脚本时随机生成的，**只在生成时打印一次**，请存到密码管理器。服务器上只保存 `$apr1$` 哈希（`/etc/nginx/.htpasswd-ctc`，`root:nginx 640`），不是明文。

> 本仓库是公开仓库，密码不写入文档。需要重置时执行 `bash 10_harden.sh --reset-pass`，重新生成 14 位随机密码。

浏览器第一次打开会弹系统对话框，输入后本次会话内不再询问；换浏览器或清缓存后需重输。

### 2.2 改密码

```bash
bash /root/10_harden.sh --reset-pass
```

会重新生成 14 位随机密码并打印。也可以手工指定：

```bash
HASH=$(openssl passwd -apr1 '你的新密码')
printf 'admin:%s\n' "$HASH" > /etc/nginx/.htpasswd-ctc
chmod 640 /etc/nginx/.htpasswd-ctc && chown root:nginx /etc/nginx/.htpasswd-ctc
systemctl reload nginx
```

### 2.3 为什么要加

改造版的 `App\Services\Auth\Admin::getAuthInfo()` 是「内置身份模式」：不读会话，恒返回内置账号且 `root=1`。也就是说后台的鉴权代码等于空转，`/admin/` 下所有页面和接口在公网裸奔。这属于改造版自带设计，不是部署引入的，但配上 500MB 上传入口风险太大，所以在 nginx 层兜住。

选 basic auth 而不是改 PHP：不动业务代码、不动注解缓存（这个项目改 PHP 注解要清 Redis 的 `_PHCR_*`，容易踩坑），两分钟生效，换网络也能用。

**注意**：basic auth 只保护 `/admin/` 路径。前台、搜索、视频播放都不受影响。

### 2.4 撤销

```bash
# 删掉 ctc-ssl.conf 里的 location ^~ /admin/ 块，然后
nginx -t && systemctl reload nginx
```

（不建议撤销，除非另外接了 OAuth 或 IP 白名单。）

## 3　8080 停用

- 配置文件已移到 `/root/nginx-backup/ctc-8080.conf.disabled.<时间戳>`
- 仓库里的 `deploy/server/video-upload/ctc.conf` 已改名为 `ctc-8080.conf.disabled`，避免脚本重跑时复活
- `07_video_upload.sh`、`09_search_db.sh` 的自检地址已从 8080 改成 443（`curl -sk`）

要恢复 HTTP 入口：

```bash
cp /root/nginx-backup/ctc-8080.conf.disabled.* /etc/nginx/conf.d/ctc.conf
nginx -t && systemctl reload nginx
```

恢复后记得在安全组里放行 8080，否则外网仍然连不上。

## 4　备份

### 4.1 策略

| 对象 | 位置 | 频率 | 保留 | 方式 |
|---|---|---|---|---|
| 数据库 | `/www/backup/ctc-YYYYmmdd-HHMM.sql.gz` | 每天 3:30 | 7 天 | `mariadb-dump --single-transaction --routines --triggers --events`，写入后 `gzip -t` 校验 |
| 视频 | `/www/backup/vod/YYYY-MM-DD/` | 每天 3:30 | 7 份 | `rsync --link-dest` 硬链接快照 |

硬链接快照的关键点：同一分区内未变更的文件只多一个目录项，不复制数据。实测两份快照 + 源目录，同一个文件的 inode 和链接数都是 `2127066 / 3`，磁盘占用没有增长（`df` 前后都是 12G/31%），首份快照 0.13 秒完成 1.3G。

### 4.2 已验证

```
数据库恢复：zcat ctc-20261105-0910.sql.gz | mariadb ctc_verify
            → 73 张表 vs 生产 73 张表，课程 9 条、视频记录 28 条，一致
视频完整性：快照文件与源文件 md5 相同（be59cf7d…）
增量行为：  第二份快照用时 0.14s，未复制数据
```

### 4.3 恢复操作

**整个数据库**（会覆盖现有数据，先停站点更稳）：

```bash
systemctl stop php-fpm
mariadb -uroot -e 'drop database ctc; create database ctc'
zcat /www/backup/ctc-20261105-0910.sql.gz | mariadb -uroot ctc
systemctl start php-fpm
redis-cli -n 3 flushdb   # 注解/业务缓存一起清，避免读旧数据
```

**单个视频误删**：

```bash
cp -a /www/backup/vod/2026-11-05/1/202611/xxx.mp4 /www/media/vod/1/202611/
chown apache:apache /www/media/vod/1/202611/xxx.mp4
```

**整目录回滚**：

```bash
rsync -a --delete /www/backup/vod/2026-11-05/ /www/media/vod/
```

### 4.4 异地备份（待配置）

现在只有本机备份。磁盘坏掉或误删整个 `/www` 时，本地备份会一起没。要真正防灾，需要配一个异地目标，编辑 `/etc/ctc/backup.conf`：

```bash
# 另一台服务器（先配免密）
REMOTE_TARGET="root@10.0.0.5:/data/ctc-backup"

# 或本机挂载的 NAS
REMOTE_TARGET="/mnt/nas/ctc-backup"
```

配置后每次备份会把 `ctc-*.sql.gz` 同步过去。**默认只同步数据库**：视频快照是硬链接，`rsync` 到远端会被展开成完整文件，1.3G×7 会撑爆对方。要单独同步视频原文件，用：

```bash
REMOTE_VOD_TARGET="root@10.0.0.5:/data/ctc-vod"
```

阿里云 OSS 需要 `ossutil`（`rsync` 不认 `oss://`），建议单独写一条 cron 只传数据库 dump。

## 6　已知限制

| 项 | 说明 |
|---|---|
| basic auth 明文传输 | 密码随每个请求走 TLS 加密通道，但浏览器会缓存凭据，共用电脑时注意退出 |
| 没有登录失败锁定 | nginx basic auth 不限次数；密码 14 位随机，暴力破解成本极高 |
| 备份在本机 | 磁盘故障会同时丢失源数据与备份，异地目标待配置 |
| 快照不等于版本历史 | 只保留 7 天，超过 7 天的改动无法回退 |
| 80 端口 warning | `nginx -t` 会提示 `conflicting server name "_" on 0.0.0.0:80`，是 `nginx.conf` 里一个被 `plaza.conf` 覆盖的默认 server 块，长期存在；ACME 验证路径在 `plaza.conf` 里，实测 `/.well-known/acme-challenge/` 返回 200，续期不受影响 |
| root 登录 | 已改为仅密钥：root 密码于 2026-11-04 换为 28 位随机串，且 `PasswordAuthentication no`（实测密码认证被拒）。私钥 `~/.ssh/ctc_ed25519` 丢失后只能走阿里云 VNC 控制台用密码登录，**私钥务必备份两份** |
