# 搜索功能修复说明

> 环境：`8.138.34.151` / `/www/ctc` / PHP 7.3 + Phalcon 3.4
> 修复时间：2026-11-04

## 1　现象

点首页右上角「搜索」，输入关键词回车，页面不是结果页，而是跳到课程列表或错误页：

```bash
curl -G --data-urlencode "query=python" https://8.138.34.151/search/
# 修复前：HTTP 302 → Location: /error/500
# 修复后：HTTP 200，标题「搜索 - python - 自学平台」
```

## 2　根因

搜索链路的实现是 `SearchController` → `Services\Logic\Search\{Course,Article,Question}` → `Services\Search\*Searcher` → `XSSearch` → **XunSearch 服务端**。三处断裂：

| 环节 | 实际情况 |
|---|---|
| 服务端进程 | 没有 `xs-searchd`（8383 端口无监听），系统里也找不到 `/usr/local/xunsearch` |
| 索引配置 | 代码读 `config/xs.course.ini`，仓库里只有 `xs.course.default.ini`，文件名对不上 |
| 索引构建 | 全项目没有任何 `XSIndex` 写入代码，也没后台重建入口 —— 即使装上服务端，索引也是空的 |

三者叠加的结果：`XSSearch` 构造时连不上 8383，抛 `XSException`，被全局异常处理重定向到 `/error/500`。

也就是说，**这个改造版从部署那天起就没跑通过搜索**，不是升级或迁移造成的。

## 3　方案选择

| 方案 | 代价 | 结论 |
|---|---|---|
| 装 XunSearch 服务端 | 需编译/安装守护进程（默认索引服务约 0.5–1G 内存），本机 2C1.87G 会挤占 MySQL 与 php-fpm；还要自写索引构建与增量同步脚本 | 放弃 |
| 改 MySQL LIKE 查询 | 只改 4 个 PHP 文件，无新进程、无新依赖 | 采用 |

课程 9 门、专栏 1 篇、问答 1 条，LIKE 的开销可以忽略；`title/summary/keywords/tags` 四个字段都带索引意义，够用。

## 4　实现

改动集中在 `app/Services/Logic/Search/`，对外接口（`search()` / `getHotQuery()` / `getRelatedQuery()`）和返回结构完全不变，控制器与模板零改动。

| 文件 | 作用 |
|---|---|
| `Handler.php` | 基类：关键词切分、LIKE 转义、分页对象构造、封面补全、分类/用户批量取名、高亮 |
| `Course.php` | 课程搜索，查 `kg_course` |
| `Article.php` | 专栏搜索，查 `kg_article` |
| `Question.php` | 问答搜索，查 `kg_question` |

要点：

- **检索条件**：`deleted=0 AND published=1`，再对 `title / summary / keywords / tags` 做 OR 匹配。
- **多词**：空格、逗号、顿号分隔，最多取 5 个词，词之间是 **AND**（`Python 算法` 能命中，`Python 前端` 不命中）。
- **中文连词**：`与 / 和 / 的 / 及 / 之 / 或 / 跟 / 同` 当分隔符处理，`容器与部署` 拆成 `容器` + `部署`，否则整串匹配不到「Docker 容器化部署」；词首尾残留的连词也会剥掉（`与算法` → `算法`）。
- **分类名参与匹配**：先按名称模糊查 `kg_category`，命中的分类 ID 作为额外条件，`计算机视觉` 这类只存在于分类、不写在标题里的词也能搜到该分类下的课程。
- **通配符转义**：用户输入里的 `%`、`_`、`\` 会被转义，避免 `%` 变成全表匹配。
- **分页**：结果为数组后用 `array_slice` 切片，再按原 `pager` 结构（`total_items / total_pages / items / first / previous / next / last`）返回，翻页链接由 `_url` + 查询参数拼出，和原 `XunSearch` 适配器一致。
- **高亮**：命中词包 `<em>`，原文先 `htmlspecialchars`，避免把用户输入当 HTML 渲染。
- **热门搜索**：原本取自 XunSearch 的词表，现改为取一级分类名（`kg_category`，按 `priority` 排序），点击即搜。
- **相关搜索**：返回空数组，侧栏该区块自动隐藏。原数据来自 XunSearch 的 `getRelatedQuery`，无索引时本就不可用。

## 5　验证

| 用例 | 结果 |
|---|---|
| `/search/?query=python` | 200，1 张课程卡，标题高亮 `<em>python</em>` |
| `/search/?query=算法` | 200，1 张卡片 |
| `/search/?query=PHP` | 200，0 张卡片（库中确实没有） |
| `/search/?query=Python 算法` | 200，1 张卡片（多词 AND） |
| `/search/?query=Python 前端` | 200，0 张卡片（多词不匹配） |
| `/search/?query=Python 与算法` | 200，1 张卡片（连词当分隔符） |
| `/search/?query=容器与部署` | 200，1 张卡片（命中「Docker 容器化部署」） |
| `/search/?query=计算机视觉` | 200，1 张卡片（分类名参与匹配） |
| `/search/?query=zzz` | 200，0 张卡片（空结果提示「没有找到」） |
| `type=article&query=wwww` | 200，1 条专栏 |
| `type=question&query=裤` | 200，1 条问答 |
| `limit=1&page=2` | 200，翻页可用，分页条正常显示 |
| 空关键词访问 `/search/` | 302 → `/course/list`（保留原行为） |
| `/search?query=python`（无尾斜杠） | 200，nginx 重写正常 |
| `query=<script>alert(1)</script>` | 无脚本输出，高亮前已转义 |
| 8080 HTTP 备用入口 | 200，同一套代码生效 |

## 6　限制

- **无词库分词**：只按空格、标点与中文连词切分。搜「前端开发」命中标题含该串的课程；搜「机器学习」不会自动拆成「机器」「学习」，也没有同义词与拼音。要真正的分词得上 SCWS 或 XunSearch。
- **顺序固定**：按 `id DESC` 排列，没有相关度排序。
- **无相关搜索**：侧栏「相关搜索」区块不再出现。
- **数据量上限**：几百到几千条课程时 LIKE 仍可用；上万条建议加 MySQL 全文索引（`ngram` 分词器）或恢复 XunSearch。

## 7　回滚

原文件已备份到 `/root/ctc_search_backup/*.php.orig`：

```bash
cd /www/ctc/app/Services/Logic/Search
for n in Handler Course Article Question; do
    cp -a /root/ctc_search_backup/$n.php.orig $n.php
done
chown apache:apache *.php
rm -rf /www/ctc/storage/cache/volt/*
systemctl restart php-fpm
```

回滚后搜索会重新变成 500，仅在其他方案（装 XunSearch）就绪后才有意义。

## 8　部署脚本

```bash
# 源目录默认取脚本同级的 search/
bash deploy/server/09_search_db.sh
```

脚本做四件事：备份原文件 → 覆盖并 `php -l` → 清 Volt 编译缓存并重启 php-fpm → 本地 8080 自检。可重复执行。
