# 学习进度 · 考试平台对接接口契约（V1.0）

> 提供方：自学平台（学习进度模块）
> 使用方：考试平台
> 契约版本：`learning-progress/1.0`
> 更新日期：2026-11-05
> 依据：《自学平台_统一身份与网关接入说明_V1.0》第 5 章（请求头与幂等）、第 8 章（事件接入）

## 0 一句话说明

自学平台把「学生完成课程」的事实推给考试平台；考试平台可以回执确认、按游标补拉、查询单个学生的进度与准入判定。**所有调用都经统一网关，服务态凭据鉴权，不依赖用户登录态。**

## 1 接入前先握手

```
GET {learning-host}/api/v1/learning/peers/exam/handshake
```

免鉴权（不返回任何学生数据），用于确认：

| 字段 | 含义 |
|---|---|
| `contract` | 契约版本，当前 `learning-progress/1.0` |
| `peerEnabled` | 我方是否已开通到考试平台的通道 |
| `appCodeMatched` | 你带的 `X-App-Code` 是否与登记值一致——**false 说明编码写错了** |
| `auth.mode` | 我方要求的入站鉴权档位：`signature` / `token` / `none` |
| `auth.signature.canonical` | 签名串的拼接形式 |
| `auth.signature.skewSeconds` | 允许的时钟偏移，默认 300 秒 |
| `outboundReady` | 我方是否已配好你的网关地址；`false` 时我方事件只入箱、暂不外发 |
| `capabilities` | 逐项能力开关与路径，未开通的会返回空路径 |
| `envelope` | 事件封套示例 |

握手是幂等的 GET，可随时复跑做自检。

## 2 鉴权

### 2.1 请求头

| 头 | 必填 | 说明 |
|---|---|---|
| `X-App-Code` | 是 | 调用方应用编码，考试平台为 `exam` |
| `X-Request-Id` | 是 | 每次请求唯一，参与签名，同时用于全链路反查 |
| `X-Timestamp` | 是 | Unix 秒级时间戳，参与签名 |
| `X-Internal-Sign` | 是（`signature` 档） | 见 2.2 |
| `Authorization: Bearer <token>` | 是（`token` 档） | 也可用 `X-Api-Key` |
| `Idempotency-Key` | 写操作必填 | 回执用回执自身 `eventId`；重放用本次操作唯一值 |

### 2.2 签名算法（HMAC-SHA256）

```
canonical = appCode + "\n" + requestId + "\n" + timestamp + "\n" + sha256_hex(rawBody)
signature = lowercase_hex( HMAC_SHA256(key = secret, message = canonical) )
```

要点：

- `rawBody` 是**原始字节**，GET 请求为空串；`sha256_hex("")` = `e3b0c442...b855`。
  签名必须对实际发出的字节做哈希，序列化方式一改（空格、字段顺序）签名就失效。
- `timestamp` 用秒，服务端允许 ±300 秒偏移，超时返回 401。
- 签名小写十六进制。

Python 示例：

```python
import hashlib, hmac, time, uuid

def sign(secret, app_code, request_id, timestamp, raw_body=b""):
    canonical = "\n".join([
        app_code,
        request_id,
        str(timestamp),
        hashlib.sha256(raw_body).hexdigest(),
    ])
    return hmac.new(secret.encode(), canonical.encode(), hashlib.sha256).hexdigest()

ts = int(time.time())
rid = "req_" + uuid.uuid4().hex
body = b'{"eventId":"rcpt_001", ...}'
headers = {
    "X-App-Code": "exam",
    "X-Request-Id": rid,
    "X-Timestamp": str(ts),
    "X-Internal-Sign": sign("＜双方约定的密钥＞", "exam", rid, ts, body),
    "Content-Type": "application/json",
}
```

> 密钥由双方线下交换，配置在我方 `peers.exam.secret`。**密钥一旦配置，我方立即强制签名校验**，之前的免签调用会返回 401，请双方约好切换时间。

## 3 我方提供给考试平台的接口

统一响应封套：

```json
{ "code": "OK", "message": "success", "data": {}, "requestId": "req_xxx" }
```

`code` 为字符串业务码，HTTP 状态码与 `code` 同时表达结果。

### 3.1 查询单个学生的学习进度

```
GET /api/v1/learning/peers/exam/students/{userId}/progress
```

| 参数 | 位置 | 说明 |
|---|---|---|
| `userId` | path | 学生对外主键，形如 `usr_10000` |

响应 `data`：

```json
{
  "userId": "usr_10000",
  "overview": {
    "course_total": 9, "completed_total": 2, "learning_total": 2,
    "lesson_completed": 11, "lesson_total": 16, "avg_progress": 30
  },
  "courses": [
    {
      "course_id": 2, "course_title": "Python 算法入门",
      "progress": 100, "status": 2, "status_text": "已完成",
      "completed_count": 4, "total_count": 4
    }
  ],
  "ruleVersion": "v1",
  "generatedAt": "2026-11-05T15:41:45Z"
}
```

### 3.2 查询准入判定（开考前回源）

```
GET /api/v1/learning/peers/exam/students/{userId}/completion/{courseId}
```

```json
{
  "userId": "usr_10000",
  "courseId": "course_2",
  "completed": true,
  "progress": 100,
  "completedChapters": 4,
  "totalChapters": 4,
  "completedAt": "2026-11-03T12:36:06Z",
  "recordId": "rec_3",
  "ruleVersion": "v1"
}
```

判定口径：课程进度 = 已完成课时 / 总课时；单个课时观看达到 **30%** 视为完成；全部课时完成才 `completed = true`。

### 3.3 回执（确认已入库）

```
POST /api/v1/learning/peers/exam/receipts
Idempotency-Key: <回执自身 eventId>
```

```json
{
  "eventId": "rcpt_20261105_001",
  "eventType": "exam.progress.ack",
  "correlationId": "evt_CE26FAD850750B24BF18",
  "payload": {
    "status": "accepted",
    "remoteId": "EXAM-2026-000456",
    "reason": ""
  }
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `correlationId` | 是 | 被确认的进度事件 `eventId`（不是回执自己的） |
| `payload.status` | 是 | `accepted` 或 `rejected` |
| `payload.remoteId` | accepted 时建议 | 考试平台侧单号，会显示在我方同步记录里 |
| `payload.reason` | rejected 时建议 | 拒收原因，写入事件备注 |

行为：

- `accepted`：事件标记「已确认」，回填 `remoteId`，不再重发。
- `rejected`：事件退回待重试，60 秒后按退避策略重发；**请确保是真实可修复的原因**，否则会反复投递。
- 同一 `eventId` 重复提交：返回 202 + `duplicate`，不重复写库。

响应：

```json
{
  "code": "OK",
  "message": "回执已确认",
  "data": {
    "receiptId": "rcpt_20261105_001",
    "targetEventId": "evt_CE26FAD850750B24BF18",
    "ackStatus": "accepted",
    "remoteId": "EXAM-2026-000456",
    "ackedAt": "2026-11-05T15:42:09Z"
  },
  "requestId": "req_xxx"
}
```

### 3.4 增量拉取（漏推补偿）

```
GET /api/v1/learning/peers/exam/pull?userId=usr_10000&afterId=0&limit=200
```

| 参数 | 说明 |
|---|---|
| `userId` | 必填 |
| `afterId` | 游标，取上次响应里的 `nextCursor` |
| `since` | 可选，ISO8601 起始时间 |
| `limit` | 可选，默认 200，上限 500 |

响应：

```json
{
  "peer": "exam", "userId": "usr_10000", "channel": "official",
  "afterId": 0, "nextCursor": 4, "hasMore": false, "limit": 200, "count": 2,
  "events": [
    {
      "eventId": "evt_22878D8040895A...",
      "eventType": "course.completed",
      "eventVersion": "1.0",
      "occurredAt": "2026-11-03T12:36:06Z",
      "userId": "usr_10000",
      "courseId": 2,
      "progress": 100,
      "deliveryStatus": 1,
      "deliveryText": "已确认",
      "acked": true,
      "remoteId": "EXAM-2026-000456",
      "payload": { "…": "完整事件封套" }
    }
  ]
}
```

**游标用自增 `id` 而不是时间戳**：同一秒可能入箱多条，用时间戳做游标会重复读或漏读。

只返回正式通道事件（`channel=official` 且类型在事件目录内），中间态进度不会出现在这里。

### 3.5 失败重放（对账后重推）

```
POST /api/v1/learning/peers/exam/replay
Idempotency-Key: <本次操作唯一值>
```

```json
{ "eventIds": ["evt_xxx", "evt_yyy"] }
```

或按条件：

```json
{ "userId": "usr_10000", "courseId": 2 }
```

响应：

```json
{
  "replayed": ["evt_xxx"],
  "skipped": [{ "eventId": "evt_yyy", "reason": "ALREADY_ACKED" }],
  "count": 1
}
```

跳过原因：`ALREADY_PENDING` / `ALREADY_SENT` / `ALREADY_ACKED` / `EVENT_NOT_ALLOWED`。

重放**只重置状态，不立即投递**，由我方投递任务（3 分钟一轮）或人工一键同步发出。

### 3.6 查询回传事件受理状态

```
GET /api/v1/learning/peers/exam/events/{eventId}
```

用于你方提交回执后确认是否被受理。

## 4 我方推送给你方的事件

```
POST {gateway}/api/v1/exam/learning/progress
```

> `push_path` 目前是占位值，**请提供正式路径**，我方改配置即可，不改代码。

请求头：

| 头 | 值 |
|---|---|
| `X-App-Code` | `learning`（我方的应用编码） |
| `Idempotency-Key` | 事件 `eventId`，重试时保持不变 |
| `X-Request-Id` | 事件入箱时的请求编号 |
| `X-User-Id` | 学生对外主键 |
| `X-Auth-Mode` | `service` |
| `X-Timestamp` | 秒级时间戳 |
| `X-Internal-Sign` | 按第 2.2 节同一算法生成 |

请求体：

```json
{
  "eventId": "evt_CE26FAD850750B24BF18",
  "eventType": "course.completed",
  "eventVersion": "1.0",
  "occurredAt": "2026-11-05T10:00:00Z",
  "sourcePlatform": "learning",
  "sourceEntityId": "course_2",
  "actorId": "usr_10000",
  "correlationId": "",
  "requestId": "req_0123456789ABCDEF",
  "data": {
    "userId": "usr_10000",
    "courseId": "course_2",
    "progress": 100,
    "completed": true
  }
}
```

**请务必按 `eventId` 去重**：网络超时会导致我方重试，同一事件可能到达多次。

返回约定：

| 你方返回 | 我方行为 |
|---|---|
| 2xx 且响应体是 JSON | 标记「已推送」，等待回执 |
| 2xx 但响应体是 HTML（网关兜底页） | 判失败并退避重试——这是我方防假成功的保护 |
| 4xx（400/401/403/404/422） | 判契约错误，**直接进死信**，需人工介入 |
| 429 / 408 / 5xx / 网络失败 | 退避重试，最多 6 次后进死信 |

退避间隔：1s / 5s / 30s / 2min / 10min / 1h。

事件目录：当前只允许 `course.completed`。中间态进度（`learning.progress.updated`）**不走正式通道**，需要时请用 3.1 / 3.4 主动查询。

## 5 错误码

| HTTP | code | 含义 | 处理建议 |
|---|---|---|---|
| 400 | `VALIDATION_ERROR` | 参数缺失或格式不对 | 修正请求 |
| 401 | `AUTH_REQUIRED` | 鉴权失败，`message` 会写明原因 | 按 message 修正：缺少签名 / 签名不匹配 / 编码未注册 / 时间戳超窗 |
| 403 | `PEER_NOT_OPEN`、`RECEIPT_NOT_OPEN`、`PULL_NOT_OPEN`、`REPLAY_NOT_OPEN`、`QUERY_NOT_OPEN` | 该能力未对我方开通 | 联系我方开通配置 |
| 403 | `PEER_SCOPE_DENIED` | 用 exam 的凭据访问了别的平台通道 | 检查路径里的对端标识 |
| 404 | `PEER_NOT_FOUND` | 对端未登记 | 检查路径 |
| 404 | `NOT_FOUND` | 学生或课程学习记录不存在 | 视为无数据 |
| 422 | `EVENT_NOT_ALLOWED` | 事件类型不在目录内 | 只用 `exam.progress.ack` |
| 422 | `TARGET_EVENT_NOT_FOUND` | 回执指向的事件不存在或不属于该对端 | 核对 `correlationId` |

401 的 `message` 是排查重点，常见值：`缺少 X-Internal-Sign`、`请求签名校验失败`、`缺少 X-Request-Id（参与签名）`、`请求时间戳超出允许窗口`、`X-App-Code 未注册`。

## 6 联调步骤

1. **握手**：`GET /peers/exam/handshake`，确认 `appCodeMatched=true`、`peerEnabled=true`。
2. **确认鉴权档位**：`auth.mode=none` 时可免签先跑通链路；拿到密钥后我方配置 `peers.exam.secret`，自动切到 `signature`，双方同时改。
3. **查询跑通**：调 3.1 / 3.2，确认能拿到真实学生数据。
4. **回执闭环**：先在测试环境收一条我方推送，回来调 3.3，确认我方页面状态从「已推送」变「已确认」并显示你方单号。
5. **补拉与重放**：用 3.4 验证游标推进（`nextCursor` 单调递增、`hasMore` 正确），用 3.5 验证幂等。
6. **压测时钟**：确认双方 NTP 正常，偏移不超过 300 秒。

自检脚本：`deploy/learning-progress/verify_exam_link.sh`（我方服务器上可直接执行，覆盖 11 个用例）。

## 7 上线检查清单

- [ ] `peers.exam.secret` 已配置，`auth.mode` 显示 `signature`
- [ ] 双方时钟偏差 < 300 秒
- [ ] `peers.exam.push_path` 已替换为考试平台提供的正式路径
- [ ] `peers.exam.base_uri` 已指向统一网关（否则为本地演示模式，事件不外发）
- [ ] 网关只放行带签名/令牌的调用，且**未匹配路径不得返回 2xx**（APISIX 的 catch-all 会造成假成功）
- [ ] 考试平台按 `eventId` 去重
- [ ] 4xx 与 5xx 的重试语义已对齐（4xx 我方进死信，不回退）
- [ ] 死信告警接收人已确定

## 8 与旧版的差异（如已按旧文档接入）

| 项 | 旧 | 新 |
|---|---|---|
| 进度查询 | 用户态接口 `GET /completion/{userId}/{courseId}` | 服务态接口 `GET /peers/exam/students/{userId}/completion/{courseId}`，无需用户令牌 |
| 鉴权 | 只依赖网关注入的可信头 | 对端自带 `X-App-Code` + 签名/令牌，身份与通道绑定 |
| 握手 | 无 | `GET /peers/exam/handshake`，先读契约再联调 |
| 越权防护 | 无 | 服务态身份只能访问自己的通道 |
